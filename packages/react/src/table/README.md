# Table implementation

`DataTable` is the sole public table component, imported from `@ifhover/leaf-ui/table`. The former `@ifhover/leaf-ui/table/tanstack` path aliases the same component. `table.tsx` contains private native semantic controls and surface styling consumed by the adapter in `../tabletanstack`. DataTable is intentionally absent from the package root, so ordinary Leaf UI root imports do not require the optional TanStack engine.

DataTable has one square, frameless appearance, with no outer canvas inset, inner frame, header cell separators or pinned-column shadows. The former `variant` and `columnDividers` props are removed; legacy JavaScript values are ignored. The header shares the content surface (white by default), uses regional `text-muted` and has one continuous 2px bottom divider across grouped and pinned cells. The divider reuses `softened-frame-color`, mixing 70% divider with the actual table surface. Colors and row interactions use `table-family`; explicit background/color and border-color overrides remain authoritative. Corners stay square regardless of a component radius override.

Headers use the regional base font size (14px by default) and 500 weight for every `size`. Block padding follows row padding: 8/12/16px for sm/md/lg by default. Together with the adapter's 24px heading content, this gives ordinary single-row headers heights of 40/48/56px. Sorting icons follow the label with a 4px gap. The first and last non-utility columns add half the regional spacing token to their logical outer padding.

`striped=true` is the default. Stripes start on the second body row, blend 2% table text into the table surface and suppress horizontal body/footer dividers. `striped=false` restores fine row dividers. Hover blends 3% primary into the table surface for one opaque color across ordinary and striped rows; selected rows keep their dedicated treatment.

`bleed=false` is the default. An opted-in DataTable directly inside a Card body or integrated tab panel receives the content area's left/right insets through private CSS properties. The DataTable wrapper expands by those amounts and cancels them with negative horizontal margins; only its direct toolbar and pagination footer restore matching padding. Vertical spacing, table cell padding, native scrolling and pagination state remain unchanged. Each DataTable resets the private insets to zero, so nested tables and standalone instances do not inherit an ancestor's extension. Card owns the generic direct-child marker contract and never imports the optional table engine. Physical sides mirror the actual Card padding, including asymmetric theme overrides and RTL; layered cards supply their compensated inner-panel padding. Additional DOM layout wrappers do not receive automatic insets.

The native Table composition API and its regional defaults are removed in this development version. Migrate native rows/cells to DataTable data and column definitions, and use `components.DataTable` for regional defaults. Row and cell callbacks use `DataTableRowProps` and `DataTableCellProps`; the `theme.components.Table` visual token slot remains available. Include the API migration in the next release notes.

The entire table consumes `surface`. An explicit `theme.components.Table.background` overrides the header and body together, preserving custom background/text pairs. Table does not consume component/global shadow overrides because it has no raised frame.

`../tabletanstack` consumes a user-owned TanStack v8 instance. Filtering, sorting, pagination, expansion, selection, column order, visibility, pinning and sizing all read from and write to that instance. The adapter does not mutate table options or keep duplicate business state. The optional peer dependency is also installed as a development dependency for examples, tests and type emission.

The mutually exclusive data/columns convenience mode creates a single instance with the usual local row models. It uses the same renderer and accepts native TanStack options, not a second column/state schema. Use `localPagination={false}` to keep pagination state while displaying the complete data set. Unless `localPagination` is explicit, `pagination={false}` disables local slicing as well as hiding the footer in data mode.

The public `useDataTable` hook shares this initialization and returns a stable native instance for custom counters, resets and bulk actions without requiring every state to be controlled. `localPagination=false` bypasses the cached local pagination model through `manualPagination`, including when toggled after mount. For a supplied instance, DataTable's `pagination` prop only owns the default footer. Native server options remain authoritative when pagination is enabled.

Data mode and `useDataTable` disable sorting by default (`options.enableSorting=false`), so ordinary headers contain no sort buttons. Opt in with `options.enableSorting=true`, then use column-level `enableSorting=false` to exclude individual columns. Control `state.sorting` and `onSortingChange` to own sorting state; add `manualSorting=true` when the application/server also owns the returned data order. Manual sorting does not implicitly enable sorting controls. Supplied native instances retain their own options without mutation.

`toolbar` adds content to the automatic layout; `pagination` accepts either a boolean or `DataTablePaginationProps`. DataTable always renders its internal toolbar, content and footer controls; search, column visibility and column order belong to application-owned TanStack state and controls. Missing row-model capabilities hide or disable the related interactions with development warnings. Unknown-total navigation preserves native attributes and events without leaking pagination-only props to the DOM.

`useDataTableSelection` maps business row keys to TanStack `rowSelection` for controlled or uncontrolled single/multiple selection and exposes `clearSelection`. Pinned positioning is internal and cannot be overridden by `getCellProps`.

`DataTableProps<T>` is the single public component props type. Its internal union keeps `table` mutually exclusive with `data`, `columns`, `rowKey`, `options` and `localPagination`; mode-specific props types are not exported. `DataTableRowKey<T>` accepts required string/number fields or functions returning either primitive; JavaScript callers retain runtime validation. Optional `DataTableColumnDef<T, TValue>` adds metadata checks to native column definitions without global augmentation. Native `ColumnDef` remains supported; `satisfies DataTableColumnMeta` is another opt-in check. Include these type-contract changes in the next release's migration notes.

Column visibility, sorting, filtering and any application-specific ordering are managed directly with TanStack state and ordinary Leaf controls; the adapter does not mount drag-and-drop sensors or keep duplicate business state.

Headers are always sticky; the public stickyHeader switch has been removed and legacy JavaScript values are ignored. The viewport measures header height to position body-only overlay tracks. A single native table preserves column alignment, grouped header associations, pinned columns and native table refs without cloned controls or duplicated rows. Height-constrained flex layouts shrink the content viewport instead of scrolling the entire table; vertical wheel chaining is contained only while the viewport actually overflows. Browsers without CSS overscroll containment use a boundary-only wheel fallback that preserves native scrolling, zooming and scrollable cell content. The caption prop and internal caption composition have been removed; use content outside the table for visible descriptions and aria-label / aria-labelledby for its accessible name. Include the removed props and simplified appearance in the next release migration notes.

The adapter passes the visible pinned-column total width to the private table control. When it exceeds the measured viewport, a private context temporarily removes horizontal sticky positioning; the header section remains vertically sticky. Resizing columns or the viewport restores pinning automatically when it fits. This presentation fallback never writes to the application's TanStack pinning state.

Ordinary tables without configured column sizes, bounds, sizing state or positive `meta.flex` use native content-based layout at 100% width. TanStack's merged default `size=150` does not count as an application-configured width. Explicit sizes/bounds, visible pinned columns, resizing and virtualization select fixed layout. In fixed layout, configured sizes and pinned/resized columns retain their TanStack widths; other unsized columns share available space with a 150px fallback minimum. Positive `meta.flex` assigns proportional weights bounded by `minSize` / `maxSize` instead. Width allocation uses only visible leaf columns and reserves 44px per utility column. ResizeObserver tracks the content area's available width, including an explicit `minWidth`; this measurement never changes the application's sizing state. All-fixed or max-capped layouts may leave unused space on the right rather than stretching a column. Resize gestures seed TanStack's sizing info from the rendered width, and resetting a resized column restores its flexible allocation. Include the default layout change in the next release's migration notes.

DataTable keeps native table semantics. Sort buttons set aria-sort on the primary sorted column; selection is conveyed through real labeled controls, rather than grid-only aria-selected. Resize handles use a focusable separator with values. Row expansion reuses small icon-only text ButtonControl actions instead of custom button paint or geometry. Detail content mounts on first expansion and survives collapse. Internal controls use FieldScope to avoid inheriting an unrelated FormField id or required state.

Ordinary grouped tables retain up to 200 rows in stable order so collapsing a group does not flip later stripes or replace child content. Their private row motion uses the shared duration and preference helpers to animate content height, opacity and cell insets, continuing from the current geometry on reversal. Closing rows become aria-hidden and inert immediately, then hidden after finishing; the last visible row owns the final divider. Virtual tables, larger groups and reduced/disabled motion update immediately. Animation completion and unmount cancel all keyframes so natural table layout remains authoritative.

Stripe parity belongs to data rows, not native DOM sibling positions: detail rows and virtual spacers do not consume a stripe. Ordinary rows use their retained data-row order so grouped collapse stays stable; virtual rows use their absolute row-model index so moving the window cannot flip their colors.

Explicit row virtualization uses TanStack Virtual and spacer rows. It measures natural row/detail heights and grouped header height; retained focused rows can introduce intermediate spacers. This is not a spreadsheet grid or column-virtualization engine. Screen-reader/device acceptance remains distinct from browser axe checks.
