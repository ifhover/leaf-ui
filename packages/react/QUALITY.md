# 组件质量验收

## 当前验收规则

本节规定本次工作应做什么检查。日期记录已移到 [质量验收历史](../../history/QUALITY-HISTORY.md)，仅证明当时的环境与执行结果；旧尺寸、API、颜色算法、数量和预算不覆盖现行规范。组件规则见 [DEVELOPMENT.md](DEVELOPMENT.md)，视觉见 [设计标准](../../DESIGN-STANDARDS.md)，颜色专项见 [颜色系统规范](../../COLOR-SYSTEM.md#自动约束与验收)。

### 工作方式

采用“基础自动检查 + 用户查看实际效果 + 必要时定向排障”。取消常驻的组件与文档浏览器自动化测试、三浏览器矩阵及其合并 / 发布门禁，不以缩小矩阵、改成定期运行或 AI 逐页手工检查替代。日常修改不默认安装浏览器、执行 Playwright、生成全量截图或维护视觉验收表。

用户查看外观与常用交互；AI 负责实现、必要的基础检查、说明受影响范围和已知问题，不能以“用户会看”为由省略基础检查，也不能替用户宣称效果已确认。不要求 AI 每次补充持久浏览器回归；只有具体缺陷确需浏览器才能定位或用户明确要求时，才按下文定向排障。以后确有反复出现、人工难发现的问题，需要新增长期浏览器专项时，先与用户确认范围和维护成本。

### 按影响选择检查

| 改动范围 | 验收要求 |
| --- | --- |
| 仅仓库维护 Markdown | 检查引用路径、标题锚点、命令与当前源码的一致性，执行 `git diff --check`；不运行组件测试或构建 |
| 组件行为、API、类型 | 执行相关单元测试和类型检查；公共 API 变化同步生成的双语 API 与使用文档 |
| 组件 SCSS、颜色、主题或共享配方 | 执行相关编译样式 / 颜色检查，按颜色规范同步生成物；共享修改按消费者类别补基础测试，不展开浏览器矩阵 |
| 公共导出、模块入口、依赖或打包链路 | 执行相关类型、生产构建、包产物及体积检查；保留 ESM / CommonJS、SSR、声明、样式按需加载和可选依赖边界 |
| 使用文档的纯文案、链接或说明 | 检查相关链接、结构与源码一致性；影响 API / AI 导出时运行相关文档测试，不运行无关组件浏览器或库构建 |
| 文档 TSX 示例、站点主题或布局 | 执行相关格式、文档类型与结构测试；最终态文档构建一次，实际页面效果由用户查看 |
| 设计资源 / Figma 导出 | 导出后做资源结构和脚本语法检查；未实际运行 Figma 时明确保留人工验收项 |

合并 / 发布的完整基础检查见下文；不因小任务临近发版就反复执行无关检查。

### 测试边界与日常执行

- 单元测试保护公开行为、原生语义、状态和算法；类型测试保护公共 API，生产构建与包检查保护真实分发入口。优先补能稳定发现问题的小型测试，不为每次修改另建测试框架。
- 颜色扫描器集中负责固定色、配方、数字档和例外预算。不要另建重复的局部扫描器、例外清单，或断言局部变量名、注释、声明顺序及 SCSS 循环写法。静态样式契约优先检查 Sass 编译后的声明，不用 jsdom 伪造真实布局结论。
- 小任务只运行相关文件和检查；同一最终态不重复执行聚合命令已包含的检查。后续只改文档时，不重跑未受影响的组件单测或库构建。
- 文档结构、完整示例提取及 API / AI 导出一致性尽量在解析与构建产物层全量检查，不通过遍历真实页面的浅深色、语言与屏宽组合重复验证相同内容。
- 不在同一本机同时运行多套重型构建与测试，避免资源争抢制造超时。失败重跑用于诊断并保留首次结果；不得以多次分散通过拼成一次全绿，或靠放宽断言掩盖缺陷。
- 日常任务结果保留在任务回复、PR 和运行报告中，不要求每个微调追加历史条目。仅在需要长期保存的阶段性验收或发布时，向 [质量验收历史](../../history/QUALITY-HISTORY.md) 补充有明确源码版本的记录。

### 合并与发布检查

- 每个正式发布提交完成一次权威的完整基础验收：`pnpm check`、`pnpm build` 及相关兼容 / 体积检查。React 18 / 19 的类型与单元兼容检查保留，不等同于浏览器矩阵。
- 优先复用同一提交、依赖锁文件、构建配置及检查范围对应的成功 CI 结果与产物；已有有效证据时，不要求 AI 在本地或下一个工作流机械重跑。合并改变提交或发布内容、依赖、配置时，检查实际发布提交，不能沿用旧结果或不匹配的产物。
- 本地定向验证用于快速反馈，CI 完整验收用于发布依据；发布与部署阶段只负责各自的版本、提交、产物来源及上线状态核验。完整质量 CI 的同提交产物复用、过期处理和轻量发布核验见 [发布操作](RELEASING.md#自动化分工与复用)。
- 基础检查失败必须定位、报告，影响本次发布的失败未解决时不宣称可以发布。取消浏览器门禁不等于已有功能缺陷自动消失；如发现实际缺陷，报告影响和风险，不以“历史已有”直接判定安全。

### 浏览器运行与报告隔离

本节只适用于按需的定向排障，不是每次修改的必做项。首屏 / hydration、真实 CSS 级联、浮层裁切或特定浏览器问题可在实际发生的页面和环境中复现；只检查与缺陷有关的状态，不自动扩展双语、浅深、宽窄屏或三浏览器矩阵。不要求把临时排障转换为持久浏览器测试。

不停止、不复用别人启动的服务，不占用别人的端口；自行启动的预览使用独立端口，临时输出使用独立运行目录，任务结束清理自己的服务。仓库不再提供常驻 Playwright 入口；按具体问题选择现有浏览器工具，不为临时排障重新安装和恢复整套测试设施。

排查生产首屏或静态页面时，使用最终源码对应的生产产物；已有匹配产物可复用，源码变化后才重建。截图只作为具体问题的辅助证据，不要求逐页截图或全量审图，不能把截图生成成功当作视觉验收。

### 检查入口

完整基础检查在仓库根目录执行；日常小任务按影响选择，不默认全部运行：

```bash
pnpm check
pnpm build
pnpm --filter @ifhover/leaf-ui measure:bundle
```

`pnpm check` 包含发布记录规则、颜色契约、Biome / SCSS 格式、组件与文档类型、单元行为、版本文档、Skill 查询和测试工具自身的测试。`pnpm build` 验证模块、类型、独立样式、服务端渲染与双语文档构建。文档 API 生成与语言资源维护见 [DEVELOPMENT.md](DEVELOPMENT.md)。

本地使用 Windows / PowerShell，不依赖 Bash / WSL 或花括号展开。单元测试定向入口为 `pnpm --filter @ifhover/leaf-ui exec vitest run <file>`；类型、文档和颜色检查复用现有脚本，不另建聚合框架。

### 报告与验收边界

- 简要列出实际命令、结果、失败或未执行的相关范围；引用 CI 时注明对应提交与运行链接。不把历史报告当作当前源码的证据，不修改期望或扩充例外基线来掩盖缺陷。
- 自动检查、用户效果确认、发布上线分别报告；构建通过不等于视觉通过，用户尚未反馈时不能替其确认。无需为每次微调附全库人工验收清单。
- 不再默认宣称三浏览器兼容、完整无障碍或真实设备验收已完成。单元行为与 SSR 检查不能替代浏览器焦点、阅读顺序、输入法和触屏体验；这些风险按实际使用反馈处理，用户要求时再定向验证。
- 移除常驻浏览器审计不取消原生语义、键盘操作和可访问名称等组件契约，也不隐藏已知对比度问题。实底前景对比度的说明与报告见 [颜色系统：角色映射与选阶](../../COLOR-SYSTEM.md#角色映射与选阶)。

### 体积与产物

生产体积使用 esbuild、tree shaking 与 gzip level 9；包含组件和运行依赖，React / ReactDOM 外置。预算以 `scripts/measure-bundle.mjs` 的可执行断言为准。Button 独立入口不得带入无关引擎，根入口和普通表单不得带入可选 TanStack Table 引擎。调整预算必须附构建报告和原因。

体积报告位于 `packages/react/.quality/bundle-report.json`；临时排障输出与构建产物均不提交 Git。万级数据、逐帧动效或其他性能专项仅在相关需求需要时执行，不是每次发布的固定步骤，结果也不是所有应用的性能保证。

### 保留与移除的自动化

当前质量 CI 保留基础检查与 React 18 / 19 兼容检查，不含浏览器任务：

- 已移除组件三浏览器任务、文档浏览器步骤及专用 artifacts，删除 `test:browser` / `test:docs:browser`、Playwright 配置、专用 spec / fixture / 辅助脚本和直接依赖。不继续维护旧浏览器失败名单，也不据此宣称既有缺陷已修复。
- 本地旧报告可继续保留在忽略目录，不为清理测试删除用户已有输出。以后若调整远端分支保护，必需检查须与现有工作流一致，不恢复已取消的浏览器门禁。
- 保留 `build-browser-entries.mjs`、`verify-browser-styles.mjs` 等生产入口与 Vite / Rspack 样式产物检查；文件名含 browser 不代表它属于待移除的浏览器测试。单元、类型、颜色、文档解析、SSR、React 兼容和体积检查不在删除范围。
- axe-core 仍用于单元层面的能力检查，Vite 仍用于生产样式入口检查，不因移除 Playwright 一并删除。发布和部署的分工见 [发布操作](RELEASING.md#自动化分工与复用)；规则与脚本已调整不代表远端新工作流已经运行通过。
