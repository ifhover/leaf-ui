# Leaf UI visual and interaction standard

Color changes must follow [the color-system contract](COLOR-SYSTEM.md): use base inputs, semantic light/dark shades plus an independent neutral 100–900 scale, and mapped roles. Family recipes are implementation reuse, not another color layer. Do not introduce near-identical component defaults, and validate final computed paint across themes. Equal values do not imply equal semantics.

## Visual Direction

The default appearance is quiet and readable. Every component uses semantic theme tokens, supports a light/dark scope, and inherits comfortable/compact density. Local component overrides and explicit sizes take precedence.

Build the desktop-tool visual language from neutral white and light-gray surfaces, fine borders, soft corners and generous container spacing around compact controls. Brand color is configurable and provides actionable emphasis; the visual structure must remain coherent when it changes. Neutral roles come from one shared scale generated from the configurable `neutralColor` seed (`#707070` by default): light mode maps text, borders and surfaces to light-appropriate steps, while dark mode maps the same scale for dark surfaces. Components consume those roles instead of hard-coding neutral values. Keep semantic status colors and readable focus feedback distinct from these neutral surfaces.

Optional theme presets may use thicker outer borders and offset shadows. Keep the default appearance unchanged when these tokens are absent. Global `borderWidth`, `controlShadow` and `surfaceShadow` and explicit component state paint must flow through ConfigProvider, including portals and API feedback. Structural dividers retain their own fine lines. Thicker borders subtract from inner control geometry and nested corner radii rather than increasing the control height. Custom shadows must preserve a distinct focus outline, disabled semantics, reduced motion and forced colors. Presets contain portable theme data; documentation decoration must not supply private component skin rules.

Steps labels have transparent backgrounds; horizontal connectors occupy their own space after the label rather than passing behind it. Avatars use a single 2px surface-colored border, including overlapping groups, without an additional outline shadow. DataTable follows layered Card: the medium-radius muted canvas holds compact 500-weight column headings, with no outer shadow or horizontal header divider. Adjacent header cells always have centered vertical separators occupying half their height. A stationary inner content frame, inset by half the regional spacing token, uses softened borders, nested corners and shadow-sm; rows scroll only inside this frame. Headers are always fixed and cannot be opted out; height-constrained flex layouts shrink the body viewport. Captions remain above the fixed column headings, and grouped headers, pinned columns and virtual rows share one native table. Sorting icons follow labels with a 4px gap; striped rows omit horizontal dividers, while striped=false restores fine row dividers. Enable columnDividers for body/footer column dividers; the first data row keeps the content surface, while stripe backgrounds start on the second data row and mix 2% table text color into the table surface. Detail and virtual spacer rows do not affect data-row stripe parity. Hover uses one opaque 3% primary tint mixed with the table surface for ordinary and striped rows, with a primary-tinted selected fill taking precedence. Explicit primarySoftColor overrides the selected fill only; expand actions reuse small icon-only text buttons and their shared neutral feedback, while drag actions retain neutral option-hover feedback. Explicit component state overrides remain authoritative. Pinned-column shadows disappear when the corresponding logical horizontal scroll edge is reached.

## Foundations And Geometry

| Foundation                            | Comfortable         | Compact             |
| ------------------------------------- | ------------------- | ------------------- |
| Base control height                   | 34 px               | 30 px               |
| Base body text                        | 14 px / 20 px       | 14 px / 20 px       |
| Secondary text                        | 13 px / 18 px       | 13 px / 18 px       |
| Large text                            | 16 px / 22 px       | 16 px / 22 px       |
| Spacing unit                          | 8 px                | 6 px                |
| Form row gap                          | 24 px               | 16 px               |
| List row vertical padding             | 12 px               | 8 px                |
| Popup option minimum height           | 30 px               | 26 px               |
| Dialog padding, block / inline        | 20 / 24 px          | 16 / 20 px          |
| Radius, small / base / medium / large | 4 / 8 / 12 / 16 px | 4 / 8 / 12 / 16 px |

Select, AutoComplete, Mentions, Tree, TreeSelect, Cascader and Dropdown rows follow the current control height (34 / 30 px comfortable / compact) with no inter-row gap. The general popup option minimum above applies to other floating lists, including Menu submenus and time columns. Explicit `optionHeight` remains authoritative for Select and AutoComplete. Dropdown icons and labels have a 12px gap.

Component size is a local choice; density is a region-wide layout choice. Compact is intended for pointer/keyboard data-heavy interfaces. Use comfortable or larger explicit controls for touch interfaces; essential targets should be at least 24 px and preferably 44 px.

Hierarchy comes from radius, borders and type rather than decoration. Default radii are 4px for small chips, 8px for controls, 12px for content and 16px for floating layers, derived from the base radius at 0.5 / 1 / 1.5 / 2. Radii step down from the outside in: dialogs, drawers and general-purpose popups use the large radius; form popups match the actual field radius, and Dropdown uses its component radius or the base radius; content surfaces (Card, Alert, Collapse, Descriptions, Transfer, Upload, FileList, DataTable, Result content, choice cards and lists) use the medium radius; buttons and fields use the base radius; checkboxes, small chips and status tags use the small radius. Content surfaces use hairline borders and muted fills; default Card adds only the lightest resting shadow, offset downward (`0 1px 2px`), while layered Card and DataTable reserve shadow-sm for their inner content frames, while other content surfaces stay flat. Outlined buttons use one subtle downward resting shadow without lifting on hover. Card and Table frames and Card's internal section lines use a softened divider (70% divider mixed with the surface), so they sit lighter than standalone dividers. Stronger shadows are reserved for layers that float (popups use `shadow-md`, dialogs `shadow-lg`) and for raised handles such as slider thumbs and selected segments. Use only weights 400, 500 and 700: body copy is 400, controls and ordinary section labels are 500, and strong text and prominent headings are 700. Text hierarchy relies on size and color: 14 px / 20 px body, 13 px / 18 px secondary text, 16 px / 22 px large text, `fontWeight` (500) for other component titles, labels, selected tabs and buttons, and `headingWeight` (700) for large Card titles and Typography headings. Small and medium default Card titles use `fontWeight` (500); large titles use 18 px / 24 px by default. Standalone CardTitle follows the same size hierarchy; layered Card keeps its compact muted heading. Option group headings in Select, Dropdown, Menu, CommandPalette, List and rich choice groups use the shared section label: 12 px minimum, weight 500, 0.04em tracking, uppercase for Latin text, muted color. Indicators that accompany text (Steps icons, Result and Upload symbols) are sized relative to the text, not to the control height.

Default geometry follows a whole-pixel grid. At the default font sizes, body, secondary and large line boxes are 20 / 18 / 22 px; the 28 / 34 / 40 px controls, default Card title line boxes (18 / 20 / 24 px), popup rows and step indicators resolve to whole pixels. Steps indicators use at least 24 px and 28 px at the large size. Explicit fractional tokens, custom font sizes, relative widths and SVG-internal coordinates can still produce fractional geometry; do not round arbitrary application content to disguise its own layout.

Inset surfaces use concentric curves: `inner radius = max(0px, outer radius - padding - border width)`. A general-purpose popup with a 16 px outer radius, 6 px padding and a 1 px border has a 9 px inner curve. Choice popups and Dropdown deliberately use field/base radius minus 2px for options, clamped at zero, matching Select independently of panel padding. Each row-local feedback layer inherits that option curve. Other nested surfaces use the shared geometry helper for unequal horizontal/vertical insets, including time columns. Theme and component padding changes update the curves automatically; small and square themes clamp to zero. Independent controls, calendar cells, tags and icons retain their semantic radii. Do not introduce clipping merely to hide a mismatch.

## Navigation And Selection

Select, AutoComplete, Mentions, Tree, TreeSelect, Cascader and Dropdown share the choice-row painter: half-strength neutral feedback (4% black), 70% inherited ink mixed with the regional surface at rest, and full inherited ink for saved, hovered and keyboard-active rows. Saved choices use checkmarks, not a permanent background; AutoComplete and Mentions use their selected ARIA state for the active candidate. Each row fades only its own background color over the shared color duration (200ms by default), without a moving highlight, opacity or inset animation; persistent checks retain their existing motion. Popup frames match their field radius, including component overrides; options use that radius minus 2px, clamped at zero. Mentions follows its Textarea field, and all shared DateInput-based date/time popups follow the DatePicker field slot. Portal geometry must not inherit a surrounding Card or Menu surface radius. Keyboard focus, disabled/search semantics, danger actions, calendar/range/time selections and the independent Menu palettes remain unchanged.

Menu is vertical-only, with layout and keyboard semantics independent of appearance. `variant` accepts `default`, `raised` and `primary`. Each appearance supplies a complete state palette, border, shadow and entry/exit timing; inline and floating navigation share one state painter instead of overriding default selection rules after the fact. `default` retains 8% black hover, press and selection fills, 80% inherited text mixed with the regional surface for unselected rows, and full text color for selection. `raised` uses a muted canvas, a selected theme surface, a 1px neutral border and `0 2px 3px -1px rgb(0 0 0 / 0.08)` shadow clipped by `inset(0 0 -4px)` to overflow only below the row; hover only deepens text, and press uses 4% black. `primary` uses readable primary ink and a 10% primary fill for selection, the same ink without a background on hover, and a 4% primary press fill, with no selection border or shadow. The latter two appearances enter over 1.2 times the standard duration (240ms by default) and clear previous selection immediately without a gray exit. All appearances preserve danger semantics, disabled behavior, keyboard outlines, reduced/disabled motion and system forced colors. Only the current page is highlighted, never its ancestors. Row radius is base radius minus 2px (6px by default), and popup frames use the base radius. Top-level height is control height plus 2px (36 / 32px), submenu height follows options (30 / 26px), and 16px icons occupy 20px slots with a 12px label gap. Inline children reserve 8px after the guide rail while keeping label alignment. Feedback never moves row geometry, labels or icons; submenus and popups retain their shared reveal motion.

Select, TreeSelect and Cascader use shared multi-selection tags: tag height is the current control height minus 8 px, with 6 px inline gaps. Field padding defaults to 3 px on both block edges and at inline-start; inline-end reserves the actual clear and arrow space. Explicit component padding overrides take precedence. Tags wrap by default; `tagWrap={false}` or `maxTagCount="responsive"` keeps one line, truncates long labels and collapses excess values into `+N`. Reserve the actual input, clear and arrow space; when a label cannot fit, show the count alone. Folding is presentation only and must not alter selection or FormData. Width-driven folding does not replay selection entry animations. TreeSelect retains expanded branches across popup unmounts; search expansion is temporary, arrows only expand, and checkbox rows accept both label and empty-area activation.

Select, AutoComplete, TreeSelect, Mentions and Cascader use the shared Scrollbar for popup overflow, including horizontal overflow in Cascader columns. Keep one scroll viewport per scroll region so virtual-list measurement, scroll callbacks and keyboard navigation use the same element. Scrollbar interactions preserve the trigger's input focus.

Tag uses borderless tinted or solid fills and the theme's small radius (6 px by default). Explicit Tag component radius overrides take precedence. Tag labels keep a 12 px minimum so compact base typography does not compress status chips, and their weight is fixed at 500 without a public weight prop. An unspecified color uses the theme color; `default` remains a compatibility alias for `primary`. Tinted labels use the corresponding readable `*-ink` role; solid labels use the matching `on-*` foreground. Brand and status fills keep their base colors, while normal text targets 4.5:1 against its surface. Explicit component paint overrides take precedence. CheckableTag and TagGroup use the tinted theme color when unselected and the solid theme color when selected. The semantic danger base is `rgb(221, 63, 46)` in the default light appearance through the global `--leaf-color-danger` token and remains shared by danger components.

Attached Badge defaults to `placement="outside"`: counts keep their inline-start edge fixed 14 px inside the target's inline-end boundary, while dots use an 8 px anchor. Both stay in place at their minimum size and grow only outward toward the inline-end edge; wider values do not re-center around the target border. `placement="inside"` anchors the indicator 6 px from the top and inline-end edges, grows inward and adds a fixed 2 px white separator ring in both appearances (the ring's outer edge is 4 px from the target). Placement does not change target geometry or interaction; ensure the target has room for the indicator without covering its content. Both placements mirror in RTL and affect attached indicators only.

Pagination defaults to surface-filled outline buttons; `variant="ghost"` keeps borderless controls. Both share control-height tokens, stable pressed geometry and a moving primary selection surface. Outline hover changes the border and text; press deepens only the border while leaving text and surface unchanged, while ghost uses neutral fills. `showTotal` accepts a boolean for a localized count or a render function. Page and page-size changes use one callback; quick jumps commit on Enter or on leaving the pagination region without overriding a clicked pagination action.

Tabs are horizontal only. Line tabs use the body text color for the selected label, muted neutral text for the others and a centered 18 px rounded indicator in the primary indicator color beneath the selected item; no continuous baseline is drawn, and the indicator moves to the next selection. The indicator sits on the tab's bottom edge and is 2 / 3 / 4 px thick by size; line tab items add 4 px of height (32 / 38 / 44 px) so a visible gap stays between the label and the indicator. Card tabs remove the surrounding bar and render the selected item as a light-gray rounded surface, with 4 px between entries and a visibly lighter neutral color for unselected labels. Card tabs keep the 28 / 34 / 40 px control sizes, 12 px inline card padding and stable pressed geometry. Segmented tabs add a muted rounded track with 3 px padding, 3 px item gaps and a nested surface-colored moving selection surface with a light resting shadow; the track is 28 / 34 / 40 px tall and labels use 14 px inline padding. The segmented selection surface moves with the standard non-overshooting easing rather than the spring curve, so it settles directly on the selected item. Set `block` for equal-width tabs; omit item content for a header-only view switcher. When labels overflow, show outlined icon-only scroll buttons on the sides with hidden content; they remain hidden until the tab header is hovered or receives keyboard focus. Tab content and panel height update immediately without entry, fade, slide or height animations; the selection indicator retains its movement animation.

## State And Color Contracts

| State           | Required behavior                                                                                                                                                                                                             |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default         | Legible text, consistent icon alignment, stable geometry                                                                                                                                                                      |
| Hover           | Color, border or shadow feedback; ordinary actions retain position and dimensions                                                                                                                                             |
| Pressed         | Immediate color/opacity feedback; buttons retain their geometry without a perimeter wave                                                                                                                                      |
| Focus-visible   | Visible focus without layout shift: Input and Select use the theme color for their border; other fields deepen their existing neutral border; buttons use a neutral keyboard outline; forced colors retain a distinct outline |
| Selected        | Semantic selected background/indicator plus ARIA state; never color alone                                                                                                                                                     |
| Disabled        | Inoperable, correct native/ARIA state; distinguish from loading                                                                                                                                                               |
| Loading         | Stable label/width when possible; expose busy state; prevent duplicate submission                                                                                                                                             |
| Error / warning | Status text and icon; focusable summary where applicable; avoid reliance on color                                                                                                                                             |
| Empty           | Explain what is empty and offer a next action when useful                                                                                                                                                                     |

Use the primary color for actionable emphasis. Use success/info/warning/danger for meaning. Muted text remains readable; custom palettes must meet WCAG contrast for their actual foreground/background combinations. Transparent derived colors use premultiplied sRGB alpha.

Default semantic bases are declared once in `colors.ts`, shared by light and dark appearances, and flow through explicit `light-N` / `dark-N` shades and mapped `--leaf-color-*` roles; components must not redeclare them. The bases are primary/success `#1e964f`, danger `#dd3f2e`, warning `#d38b11` and info `#1677ff`. A supplied primary stays the base input: it is never rewritten and is not forced to step 500. Feedback visual APIs use `danger`; legacy `error` inputs are accepted only as compatibility aliases and normalize to `danger`. Form validation, progress and step states retain their `error` status names and consume the danger token.

Keep explicit primary fills intact in both appearances. Light and dark modes use the same semantic bases and named shades; appearance switches roles instead of recoloring the base or generating another scale. Ink keeps the original base when it reaches 4.5:1 against its actual surfaces; otherwise it selects the smallest suitable named light/dark adjustment. Primary indicators are selected independently to reach 3:1 against the current surfaces. Dim solid buttons gain a subtle boundary while retaining their on-primary label. Components that use primary focus indicators use the visible indicator when the raw primary is dim; other fields and buttons keep neutral focus feedback. Never lighten every primary fill just to make primary text readable; explicit component/state, foreground and focus overrides retain precedence.

Solid-fill foreground roles default to white without automatic contrast selection; explicit on-* overrides may use black; do not create hue-tinted foregrounds per semantic family. Solid Buttons keep a transparent default border even when their base matches the surrounding surface; do not add an automatic contrast border. Explicit global, component and state border overrides and system forced-colors remain supported. Keep the independent on-primary / on-success / on-danger / on-warning / on-info roles even when their values match. Light and dark modes may share values; mode-specific colors require an actual visual or contrast need, not a complete duplicated matrix.

Checkbox, Radio and Switch checked fills use the original primary base and on-primary content. The primary indicator is reserved for boundaries and selection indicators where the raw fill needs separation from its surface; never pair a scale-derived fill with a foreground derived from another color. Explicit component paint overrides retain precedence.

Warning glyphs, field accents and status fills use the shared clear amber base (`#d38b11`). Warning text derives a readable ink independently; warning Tag dots retain the warning base while soft labels consume readable warning ink. Do not darken every warning accent to achieve text contrast.

Unselected options use the mapped `--leaf-color-option-hover` neutral role for pointer, keyboard candidate and pressed feedback. Select, AutoComplete, Cascader, Tree, TreeSelect, time columns, Dropdown, CommandPalette and Menu share it. In Select, Dropdown, AutoComplete, Cascader, Tree, TreeSelect option lists and Menu, persistent selection also uses the same neutral gray fill and ordinary text, with a checkmark where the component needs a persistent marker; time columns and pagination retain their own selected treatments. In Select, TreeSelect and Tree the moving highlight owns the only gray fill: it starts on the selected value, or on the first available row when an open TreeSelect has no value, follows hovered or keyboard candidates, and returns to the selected value when the pointer leaves the list. The selected row keeps its checkmark without a second resting fill; checkbox mode uses its checkbox as the persistent marker. Select, TreeSelect and Tree rows have no extra vertical gaps: a normal row equals the field height (34 / 30 px comfortable / compact; follow explicit component tokens), and long labels wrap and grow the row. Tree hierarchy indentation remains part of the row layout. Changing the selected value updates the trigger label immediately; do not replay inside-text movement. Cascader replaces a deeper column immediately when the parent changes, without a fade that reads as flicker. Suggestion candidates remain neutral even when their listbox uses `aria-selected` to announce navigation. Moving backgrounds interpolate both position and color; opaque fills prevent darkening when they cross selected rows, and static rows must not add a second hover / pressed fill. Disabled options receive no interaction feedback; danger actions retain their red semantic fill. Color transitions share `--leaf-motion-color` (currently the standard motion duration) across fields, buttons, menu surfaces and popup rows.

Ordinary action feedback uses 120–200 ms easing. Dialogs and drawers can use up to 320 ms; drawers slide without overshoot. Messages and notifications enter as one unit, without inner icon/text springs. Selection indicators may move to the newly selected item; their animation must not move the control itself. Cards retain their position and surface on hover. Honor system reduced motion and `theme.motion={false}`; animation never gates functionality.

Buttons and compact actions share the same paint-transition duration and easing for hover, press and recovery. Loading content uses that same easing without a spring. Danger changes only the semantic palette, not motion, decoration or geometry. Buttons respond through color transitions without a perimeter wave. Pointer activation adds no focus halo. Keyboard focus uses a neutral outline and remains visible in forced colors. Input and Select express focus or an open popup with the theme color on their border without adding an outer ring; other field types retain their neutral border behavior, validation states retain their semantic border colors, and explicit component focus tokens take precedence.

Text buttons use normal button height and inline padding, with body text and a transparent resting surface. Hover uses the neutral option-hover background at 50% opacity; press uses its full strength without geometry changes. Compact clear, visibility and close actions reuse the text-action recipe while retaining owner-sized hit areas. Link buttons use the primary base, not contrast-adjusted primary ink; explicit overrides and danger semantics retain precedence.

Solid and link buttons keep their resting appearance on hover and change only while pressed. Solid buttons deepen on press. Outlined buttons deepen their border on hover using `border-hover`, or `danger-ink` for danger actions. Press only blends the actual background equally with `surface-muted`, a subtle neutral gray, restoring it on release. Text, border, shadow and geometry stay unchanged from the current hover or focus state. Border and background use the shared color-transition duration and easing. Solid press shades mix 10% black into the base without quantization; labels stay white unless explicitly overridden. Explicit interaction tokens take precedence. Danger actions retain semantic colors. All variants retain their geometry.

## Surfaces And Composite Components

Dialog headings, form edges and footer actions share the same inline padding in the default surface. The body has sufficient separation from both heading and actions. A notification close action occupies only the heading row. Icons are decorative when the accompanying text already conveys the meaning. Every icon-only action needs an accessible name.

Modal uses a theme-derived muted canvas with spacing-based sections by default. The plain header and footer share the same inline padding, and headers without a description use a compact 16 px top inset. The default cancel action uses the outlined button appearance. `variant="card"` keeps the same canvas and places the body on a 6 px inset, borderless medium-radius content surface. Its 14 px heading uses heading weight and a 22 px line box, aligned with the content text start edge; the close target remains 8 px inside the content card's right edge while footer actions align with the card. The header uses a 12 px top inset, followed by a single 12 px section gap before the content surface and a 10 px gap from the content card to footer buttons. Footer top padding is zero to avoid doubling that gap; the bottom inset is 10 px, and the heading text is offset 2 px downward within its text column. Body padding independently controls the distance from content to the card edge. The 24 px close target contains a 16 px icon in the body text color, with a transparent resting background, a deeper standard neutral hover background and the small radius (6 px by default). Drawer retains section dividers and a muted footer by default; `divided={false}` groups its content with spacing. Their heading icons share a neutral circular base. Confirm is an API-only decision prompt: a compact 420 px surface, spacing-based sections, a bare semantic glyph beside the explanation and no background base or section dividers. Its heading starts at the content edge, independently of the body icon. Popconfirm and Notification use a bare semantic glyph aligned with the title line. Modal and Drawer footers share 12 px vertical insets; spacing-only dialog and Confirm footers use 12 px below their actions. Titles and supporting descriptions share an independent text column. The close action remains on the inline end. Body content scrolls without moving the heading or footer. Borders and surfaces derive from the current light/dark region, including custom palettes and density.

Date, time and range picker panels share `panelVariant="card"` with the Modal card treatment. The popup is a muted canvas; the calendar, time columns, paired panels and preset region use inset content surfaces with the medium radius. Picker footers lose their divider and tinted strip so they sit directly on the canvas, aligned with the content surface. Keep the same hierarchy in light, dark, RTL and narrow layouts.

The full Calendar uses an editorial, borderless grid. A large localized month name carries the heading, with the year as a lighter companion and Today plus paired navigation controls at the trailing edge. Date, month and year views use open 7-, 4- and 3-column layouts; date cells never draw individual frames. Selection fills the whole date cell with a quiet primary tint and marks the numeral with a solid circular label. Today uses primary-colored text and a small dot instead of an outline. `cellRender` content sits below the numeral in one truncated line. Compact calendars keep a 32px borderless date grid without changing their surrounding picker structure.

Card no longer exposes `hoverable` or adds hover lift; it keeps a subtle resting shadow offset downward, and `bordered` remains available. Card `size` offers small, default and large layouts: body padding defaults to 16 / 20 / 24 px, heading insets to the same 16 / 20 / 24 px and title text to 14 / 16 / 18 px. Default Card uses equal outer insets on all four sides (16 / 20 / 24 px). Header and footer share the body reading edge, without duplicating interior section gaps; explicit component padding remains authoritative. `selected` adds a primary-color outer border (including when bordered=false) and removes both outer and layered-panel shadows without changing geometry or surface; an explicit component borderColor still takes precedence. Selection is visual only and does not add a click target, role or tab stop. Embedded Tabs follow the Card size unless explicitly overridden; child controls keep their own sizes. Card headings use `headingWeight` (700 by default) and equal vertical insets; the body does not add a second inset below an undivided header. Card always groups the heading, body and footer with spacing; it has no public `divided` mode. `variant="layered"` (formerly the unreleased `inset` appearance) has no outer shadow and keeps a small muted heading and footer on the canvas; `description` is not displayed. Only the cover, tabs and body sit on the content surface, inset by 4 px on the sides and bottom (6 px above an unheaded panel). Layered heading sizes are 12 / 12 / 13 px at weight 500. Inner corners subtract the border width and 2 px from the outer radius (9 px versus 12 px by default), and the soft downward shadow uses `shadow-sm`, with a 6 px blur and up to 6 px of visible overflow on each side and below, without extending above the panel. Content padding compensates for the inset so tab labels and body content share a reading edge; layered headings sit 5 px toward inline start from that edge by reducing header inline-start padding, without negative heading margins. Layered heading top insets are 6 / 8 / 10 px and bottom insets are 2 / 4 / 6 px; the header reserves a content row equal to a default outlined Tag (small line height plus 6 px), keeping tagged and untagged single-line headings equally tall; trailing header content aligns with the content card edge. Footer padding is zero above and 4 px below its actions, with the content card's 4 px bottom margin owning the gap. Footer actions align with the content card edge below it. Checkbox/Radio card choices have one full clickable label, a neutral icon base, a title/description column and a trailing native control. Groups may arrange these as a responsive grid or one list with shared borders and row separators. Selected borders use the primary color without gradients or lifting. Status tags are non-interactive, and supporting text is an accessible description rather than part of the choice name. Neutral Alert surfaces preserve semantic icon colors and announcement roles.

Card can integrate top line tabs through its `tabs` configuration. With a heading, navigation sits below the title and description without an intervening divider; without a heading, tabs fill the entire heading height with vertically centered labels and Card actions move to the trailing edge. Replacement headings derive their minimum height from the Card title line and symmetric heading insets, respect larger explicit tab sizes, and have no top-only outer padding. One full-width divider runs under the entire tab bar, including its actions; the selected underline overlays that divider so its thickness matches standalone line tabs. Tab labels and panels align with the Card content edge, panel insets and header surfaces inherit Card tokens, and tab size follows Card size unless explicitly set. The footer keeps the same spacing-based treatment. Reuse Tabs navigation, overflow, content retention and animation rather than creating a second tab state system; loading replaces panel content while navigation remains mounted.

CardTitle reuses Card title typography outside a Card, without adding a surface or padding. Its small, default and large sizes match Card titles (14 / 16 / 18 px at the default base font size, at weight 700 by default); both Card and CardTitle default to an h3 heading, so callers should not specify a level unless the surrounding document outline requires it. `description` sits beneath the heading and `extra` at its trailing edge, matching the Card heading area. Both use the regional font family, base font size and heading weight. Card owns its internal title size and does not consume standalone CardTitle default props; user-supplied CardTitle elements still receive their regional defaults.

FileList uses one shared frame and row separators for text and thumbnail lists. Visuals, file information and actions occupy separate columns; names truncate within their column, while type and optional size remain secondary. Upload state, progress and errors belong to the information column. Preview buttons, download links, removal and Upload actions share square geometry. Picture cards keep a stable preview ratio and align their actions at the bottom. Missing sizes leave no empty placeholder, failed thumbnails retain a type icon, and asynchronous removal feedback stays with its file. No row shadow or hover lift is applied.

ConfigProvider remains the configuration entry. Base colors, radius and height derive related geometry; advanced `dividerColor`, component `borderColor`, `headerBackground` and `footerBackground` provide selective overrides. CSS variables are consumption points for application styling. Filled actions and checkmarks remain solid colors, and single-line controls keep the 34px base height.

Buttons expose solid, outline and link appearances; outline is the default. Outlined actions use a content surface, body text, a visible neutral border and one subtle resting shadow. Hover deepens the neutral border using `border-hover`; press only adds a subtle neutral gray background by blending the actual surface equally with `surface-muted`, preserving text, border, shadow and geometry. Both feedback changes transition smoothly. Danger outlines retain their semantic text and borders. Link actions use theme-colored text with no border, padding or control-height minimum; hover keeps the resting color, press deepens primary text or underlines readable danger text, and activation has no wave. Explicit component state overrides retain precedence. Alerts use one neutral surface with semantic icon colors. Result icons sit on the same muted circular base for every status. Table surfaces use the same base radius as buttons with a softened frame and the Card resting shadow. Tables use 12 px bold, slightly muted column headers and divider-colored separators, and fill their container before horizontal overflow; a minimum width remains a lower bound. Scrollbar tracks overlay content and appear on hover, scroll or keyboard focus; dragging must neither steal input focus nor add a pointer focus outline.

The segmented Tabs rail, ColorPicker format rail, layered Card outer canvas, Modal canvas and card-style picker canvas directly share `--leaf-color-surface-muted`. Explicit `mutedSurfaceColor` paints the exact same color across these canvases without mixing borders or surfaces again. Selected sliders and inset content panels remain on `--leaf-color-surface`; explicit component overrides and nested themes retain precedence. Semantic shade names express fixed sRGB white/black percentages; neutral `100–900` remains a separate lightness scale.

## Development Migration

Development migration: Button now exposes `solid`, `outline` and `link`; `outline` is the default, and the former public `ghost` and `soft` appearances are removed. Replace secondary soft actions by omitting `variant`, and keep borderless composite controls private to their owning components. Remove Alert `variant` props. Comfortable controls now derive 28 / 34 / 40 px sizes; compact controls use a 30 px base. Set `theme.controlHeight` explicitly when an application needs to retain its former sizing. Content surfaces move from the large to the new medium radius (`borderRadiusMd` / `--leaf-radius-md`) and drop their previous default shadow; Card and Table keep only a subtle resting shadow offset downward. The default base font moves to 14 px / 20 px, small text to 13 px / 18 px (`fontSize - 1px`) and large text to 16 px / 22 px (`fontSize + 2px`); Card and CardTitle sizes become 14 / 16 / 18 px at heading weight (700 by default), and tags and section labels keep a 12 px minimum. `lineHeight` now accepts `number | string` and defaults to 20 px. Numbers from greater than 0 through 4 keep the former multiplier meaning (`1.6` produces a 22.4 px line box at the default font size); other numbers are pixels, and strings are CSS lengths. Card and CardTitle line boxes are 20 / 22 / 24 px, and step indicators are at least 24 px (28 px at the large size). Button inline padding derives from its actual height (0.42 times the height, 14.28 px at 34 px), with explicit component padding taking precedence for every size; component titles other than Card use `fontWeight` instead of `headingWeight`; rich choice legends use section labels; replace controlled `Confirm` / `ConfirmProps` with `useConfirm().confirm(options)` / `ConfirmOptions`, and move rich confirmation flows to Modal; Confirm retains a bare body icon; Tag exposes soft and outline, removes solid, and includes a default optional 6px dot; outline uses a neutral content surface, neutral border, body text and pill radius, while soft retains the small radius; both keep weight 500 and existing size geometry; migrate solid Tags to soft or outline and set dot={false} for text-only tags; CheckableTag and TagGroup use outline when unchecked and soft when checked; popups use `shadow-md`; Pagination uses outlined page buttons by default. Include these compatibility changes in the next release's migration notes.

## Acceptance

Acceptance uses keyboard behavior, geometry assertions, axe, SSR, build/package checks and manual inspection in both themes and densities. Screenshot baseline comparisons are deliberately deferred. Current verification requirements live in [QUALITY.md](packages/react/QUALITY.md#当前验收规则). [IMPLEMENTATION-BATCHES.md](IMPLEMENTATION-BATCHES.md) and [ACCESSIBILITY.md](packages/react/ACCESSIBILITY.md) are historical evidence with date-specific coverage limits, not current implementation rules.

Workbench refresh migration: the default base radius changes from 10px to 8px; small / medium / large derivation changes to 0.5 / 1.5 / 2 so content surfaces retain 12px and floating layers retain 16px. Replace weight 600 with 500 for ordinary labels or 700 for strong headings; `headingWeight` and `tokens.fontWeight` accept only 400 / 500 / 700. Card and Table resting shadows reduce to `shadow-xs`. Explicit component and state styles still take precedence.
