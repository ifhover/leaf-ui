# Leaf UI visual and interaction standard

Color changes must follow [the color-system contract](COLOR-SYSTEM.md): reuse semantic roles and family recipes, do not introduce near-identical component defaults, and validate final computed paint across themes. Equal values do not imply equal semantics.

The default appearance is quiet and readable. Every component uses semantic theme tokens, supports a light/dark scope, and inherits comfortable/compact density. Local component overrides and explicit sizes take precedence.

Build the desktop-tool visual language from neutral white and light-gray surfaces, fine borders, soft corners and generous container spacing around compact controls. Brand color is configurable and provides actionable emphasis; the visual structure must remain coherent when it changes. Light foundations use text `#202020`, muted text `#707070`, surface `#ffffff`, muted surface `#f5f5f5` and border `#e2e2e2`. Dark foundations use text `#ededed`, muted text `#aaaaaa`, surface `#1c1c1c`, muted surface `#272727` and border `#3b3b3b`. Keep semantic status colors and readable focus feedback distinct from these neutral surfaces.

Optional theme presets may use thicker outer borders and offset shadows. Keep the default appearance unchanged when these tokens are absent. Global `borderWidth`, `controlShadow` and `surfaceShadow` and explicit component state paint must flow through ConfigProvider, including portals and API feedback. Structural dividers retain their own fine lines. Thicker borders subtract from inner control geometry and nested corner radii rather than increasing the control height. Custom shadows must preserve a distinct focus outline, disabled semantics, reduced motion and forced colors. Presets contain portable theme data; documentation decoration must not supply private component skin rules.

Steps labels have transparent backgrounds; horizontal connectors occupy their own space after the label rather than passing behind it. Avatars use a single 2px white border, including overlapping groups, without an additional outline shadow. DataTable always uses the base radius, an untinted header surface and the same softened frame and downward resting shadow as Card. Headers use headingWeight and a slightly muted body color in both modes, with sorting icons 4px after the label. All headers have a 1px bottom divider; striped rows omit horizontal dividers, while striped=false restores fine row dividers. Enable columnDividers for column dividers; stripe backgrounds start on the first body row and mix 2% table text color into the table surface. Hover uses one opaque 3% primary tint mixed with the table surface for ordinary and striped rows, with a primary-tinted selected fill taking precedence. Explicit primarySoftColor overrides the selected fill and internal action feedback. Pinned-column shadows disappear when the corresponding logical horizontal scroll edge is reached.

Component size is a local choice; density is a region-wide layout choice. Compact is intended for pointer/keyboard data-heavy interfaces. Use comfortable or larger explicit controls for touch interfaces; essential targets should be at least 24 px and preferably 44 px.

Hierarchy comes from radius, borders and type rather than decoration. Radii step down from the outside in: dialogs, drawers and popups use the large radius; content surfaces (Card, Alert, Collapse, Descriptions, Transfer, Upload, FileList, Result content, choice cards and lists) use the medium radius; buttons, fields and Table frames use the base radius; checkboxes, small chips and status tags use the small radius. Content surfaces use hairline borders and muted fills; Card and Table add only the lightest resting shadow, offset downward (`0 3px 7px` / `0 1px 2px`), while other content surfaces stay flat. Outlined buttons use one subtle downward resting shadow without lifting on hover. Card and Table frames and Card's internal section lines use a softened divider (70% divider mixed with the surface), so they sit lighter than standalone dividers. Stronger shadows are reserved for layers that float (popups use `shadow-md`, dialogs `shadow-lg`) and for raised handles such as slider thumbs and selected segments. Text hierarchy relies on size and color: 14 px / 20 px body, 13 px / 18 px secondary text, 16 px / 22 px large text, `fontWeight` (500) for other component titles, labels, selected tabs and buttons, and `headingWeight` (600) for Card titles and Typography headings. Option group headings in Select, Dropdown, Menu, CommandPalette, List and rich choice groups use the shared section label: 12 px minimum, weight 500, 0.04em tracking, uppercase for Latin text, muted color. Indicators that accompany text (Steps icons, Result and Upload symbols) are sized relative to the text, not to the control height.

Default geometry follows a whole-pixel grid. At the default font sizes, body, secondary and large line boxes are 20 / 18 / 22 px; the 28 / 34 / 40 px controls, Card title line boxes (18 / 20 / 22 px), popup rows and step indicators resolve to whole pixels. Steps indicators use at least 24 px and 28 px at the large size. Explicit fractional tokens, custom font sizes, relative widths and SVG-internal coordinates can still produce fractional geometry; do not round arbitrary application content to disguise its own layout.

Inset surfaces use concentric curves: `inner radius = max(0px, outer radius - padding - border width)`. A default popup has a 16 px outer radius, 6 px padding and a 1 px border, so its options use 9 px. Hover, selected and moving highlight layers share that curve. The shared geometry helper accounts for unequal padding with horizontal/vertical corner radii, including the extra insets in Cascader and TimePicker. Theme and component padding changes update the curves automatically; small and square themes clamp to zero. Independent controls, calendar cells, tags and icons retain their semantic radii. Do not introduce clipping merely to hide a mismatch.

Menu is vertical-only, with layout and keyboard semantics independent of appearance. `variant` accepts `default`, `raised` and `primary`. Each appearance supplies a complete state palette, border, shadow and entry/exit timing; inline and floating navigation share one state painter instead of overriding default selection rules after the fact. `default` retains 8% black hover, press and selection fills, 80% inherited text mixed with the regional surface for unselected rows, and full text color for selection. `raised` uses a muted canvas, a selected theme surface, a 1px neutral border and `0 2px 3px -1px rgb(0 0 0 / 0.08)` shadow clipped by `inset(0 0 -4px)` to overflow only below the row; hover only deepens text, and press uses 4% black. `primary` uses readable primary ink and a 10% primary fill for selection, the same ink without a background on hover, and a 4% primary press fill, with no selection border or shadow. The latter two appearances enter over 1.2 times the standard duration (240ms by default) and clear previous selection immediately without a gray exit. All appearances preserve danger semantics, disabled behavior, keyboard outlines, reduced/disabled motion and system forced colors. Only the current page is highlighted, never its ancestors. Row radius is base radius minus 2px (8px by default), and popup frames use the base radius. Top-level height is control height plus 2px (36 / 32px), submenu height follows options (30 / 26px), and 16px icons occupy 20px slots with a 12px label gap. Inline children reserve 8px after the guide rail while keeping label alignment. Feedback never moves row geometry, labels or icons; submenus and popups retain their shared reveal motion.

Select, TreeSelect and Cascader use shared multi-selection tags: tag height is the current control height minus 8 px, with 6 px inline gaps. Field padding defaults to 3 px on both block edges and at inline-start; inline-end reserves the actual clear and arrow space. Explicit component padding overrides take precedence. Tags wrap by default; `tagWrap={false}` or `maxTagCount="responsive"` keeps one line, truncates long labels and collapses excess values into `+N`. Reserve the actual input, clear and arrow space; when a label cannot fit, show the count alone. Folding is presentation only and must not alter selection or FormData. Width-driven folding does not replay selection entry animations. TreeSelect retains expanded branches across popup unmounts; search expansion is temporary, arrows only expand, and checkbox rows accept both label and empty-area activation.

Select, AutoComplete, TreeSelect, Mentions and Cascader use the shared Scrollbar for popup overflow, including horizontal overflow in Cascader columns. Keep one scroll viewport per scroll region so virtual-list measurement, scroll callbacks and keyboard navigation use the same element. Scrollbar interactions preserve the trigger's input focus.

Tag uses borderless tinted or solid fills and the theme's small radius (6 px by default). Explicit Tag component radius overrides take precedence. Tag labels keep a 12 px minimum so compact base typography does not compress status chips, and their weight is fixed at 500 without a public weight prop. An unspecified color uses the theme color; `default` remains a compatibility alias for `primary`. Tinted labels follow the tag's own color, except warning uses the derived readable warning ink; solid labels use white, except warning uses `--leaf-color-on-warning` against the warning fill. CheckableTag and TagGroup use the tinted theme color when unselected and the solid theme color when selected. The semantic danger base is `rgb(221, 63, 46)` in the default light appearance through the global `--leaf-color-danger` token and remains shared by danger components.

Attached Badge counts keep their inline-start edge fixed 14 px inside the target's inline-end boundary, while dots use an 8 px anchor. Both stay in place at their minimum size and grow only outward toward the inline-end edge; wider values do not re-center around the target border. Keep the anchor width-independent and mirrored in RTL.

Pagination defaults to surface-filled outline buttons; `variant="ghost"` keeps borderless controls. Both share control-height tokens, stable pressed geometry and a moving primary selection surface. Outline hover changes the border and text; press deepens only the border while leaving text and surface unchanged, while ghost uses neutral fills. `showTotal` accepts a boolean for a localized count or a render function. Page and page-size changes use one callback; quick jumps commit on Enter or on leaving the pagination region without overriding a clicked pagination action.

Tabs are horizontal only. Line tabs use the body text color for the selected label, muted neutral text for the others and a centered 18 px rounded indicator in the primary indicator color beneath the selected item; no continuous baseline is drawn, and the indicator moves to the next selection. The indicator sits on the tab's bottom edge and is 2 / 3 / 4 px thick by size; line tab items add 4 px of height (32 / 38 / 44 px) so a visible gap stays between the label and the indicator. Card tabs remove the surrounding bar and render the selected item as a light-gray rounded surface, with 4 px between entries and a visibly lighter neutral color for unselected labels. Card tabs keep the 28 / 34 / 40 px control sizes, 12 px inline card padding and stable pressed geometry. Segmented tabs add a muted rounded track with 3 px padding, 3 px item gaps and a nested white moving selection surface with a light resting shadow; the track is 28 / 34 / 40 px tall and labels use 14 px inline padding. The segmented selection surface moves with the standard non-overshooting easing rather than the spring curve, so it settles directly on the selected item. Set `block` for equal-width tabs; omit item content for a header-only view switcher. When labels overflow, show outlined icon-only scroll buttons on the sides with hidden content; they remain hidden until the tab header is hovered or receives keyboard focus. Tab content and panel height update immediately without entry, fade, slide or height animations; the selection indicator retains its movement animation.

| Default         | Legible text, consistent icon alignment, stable geometry                                                                                                                                                                      |
| Hover           | Color, border or shadow feedback; ordinary actions retain position and dimensions                                                                                                                                             |
| Pressed         | Immediate color/opacity feedback; buttons retain their geometry without a perimeter wave                                                                                                                                      |
| Focus-visible   | Visible focus without layout shift: Input and Select use the theme color for their border; other fields deepen their existing neutral border; buttons use a neutral keyboard outline; forced colors retain a distinct outline |

| Disabled        | Inoperable, correct native/ARIA state; distinguish from loading                                                                                                                                                               |
| Loading         | Stable label/width when possible; expose busy state; prevent duplicate submission                                                                                                                                             |

Use the primary color for actionable emphasis. Use success/info/warning/danger for meaning. Muted text remains readable; custom palettes must meet WCAG contrast for their actual foreground/background combinations. Transparent derived colors use premultiplied sRGB alpha.

Default semantic base colors are declared once in `colors.ts` and flow through the generated `--leaf-color-*` palette; components must not redeclare them. The default light bases are primary/success `#1e964f`, danger `#dd3f2e`, warning `#d38b11` and info `#1677ff`. Feedback visual APIs use `danger`; legacy `error` inputs are accepted only as compatibility aliases and normalize to `danger`. Form validation, progress and step states retain their `error` status names and consume the danger token.

Keep explicit primary fills intact in both appearances. Dark themes derive primary ink and indicators separately from the brand fill: ink targets 4.5:1 against content/muted surfaces, selected indicators target 3:1, and dim solid buttons gain a subtle boundary while retaining their on-primary label. Components that use primary focus indicators use the visible indicator when the raw primary is dim; other fields and buttons keep neutral focus feedback. Never lighten every primary fill just to make primary text readable; explicit component/state, foreground and focus overrides retain precedence.

Warning glyphs, field accents and status fills use a clear amber (`#d38b11` in light, `#ffc53d` in dark). Warning text derives a darker or lighter readable ink independently; solid warning tags choose a contrasting label. Do not darken every warning accent to achieve text contrast.

Unselected options use one opaque neutral hover color (`--leaf-color-option-hover`, 9% text mixed with 91% surface; default light `#ebebeb`, dark `#2f2f2f`) for pointer, keyboard candidate and pressed feedback. Select, AutoComplete, Cascader, Tree, TreeSelect, time columns, Dropdown, CommandPalette and Menu share it. In Select, Dropdown, AutoComplete, Cascader, Tree, TreeSelect option lists and Menu, persistent selection also uses the same neutral gray fill and ordinary text, with a checkmark where the component needs a persistent marker; time columns and pagination retain their own selected treatments. In Select, TreeSelect and Tree the moving highlight owns the only gray fill: it starts on the selected value, or on the first available row when an open TreeSelect has no value, follows hovered or keyboard candidates, and returns to the selected value when the pointer leaves the list. The selected row keeps its checkmark without a second resting fill; checkbox mode uses its checkbox as the persistent marker. Select, TreeSelect and Tree rows have no extra vertical gaps: a normal row equals the field height (34 / 30 px comfortable / compact; follow explicit component tokens), and long labels wrap and grow the row. Tree hierarchy indentation remains part of the row layout. Changing the selected value updates the trigger label immediately; do not replay inside-text movement. Cascader replaces a deeper column immediately when the parent changes, without a fade that reads as flicker. Suggestion candidates remain neutral even when their listbox uses `aria-selected` to announce navigation. Moving backgrounds interpolate both position and color; opaque fills prevent darkening when they cross selected rows, and static rows must not add a second hover / pressed fill. Disabled options receive no interaction feedback; danger actions retain their red semantic fill. Color transitions share `--leaf-motion-color` (currently the standard motion duration) across fields, buttons, menu surfaces and popup rows.

Ordinary action feedback uses 120–200 ms easing. Dialogs and drawers can use up to 320 ms; drawers slide without overshoot. Messages and notifications enter as one unit, without inner icon/text springs. Selection indicators may move to the newly selected item; their animation must not move the control itself. Cards retain their position and surface on hover. Honor system reduced motion and `theme.motion={false}`; animation never gates functionality.

Buttons respond through color transitions without a perimeter wave. Pointer activation adds no focus halo. Keyboard focus uses a neutral outline and remains visible in forced colors. Input and Select express focus or an open popup with the theme color on their border without adding an outer ring; other field types retain their neutral border behavior, validation states retain their semantic border colors, and explicit component focus tokens take precedence.

Solid and link buttons keep their resting appearance on hover and change only while pressed. Solid buttons deepen on press. Outlined buttons also keep their resting appearance on hover; while pressed they deepen only the border to `primary-active`, or `danger-active` for danger actions, while the text, background and shadow stay unchanged. Outlined buttons have a subtle resting shadow. Derived shades retain readable labels and explicit interaction tokens take precedence. Danger actions retain semantic colors. All variants retain their geometry.

Dialog headings, form edges and footer actions share the same inline padding in the default surface. The body has sufficient separation from both heading and actions. A notification close action occupies only the heading row. Icons are decorative when the accompanying text already conveys the meaning. Every icon-only action needs an accessible name.

Modal uses a theme-derived muted canvas (default light `#f9f9f9`) with spacing-based sections by default. The plain header and footer share the same inline padding, and headers without a description use a compact 16 px top inset. The default cancel action uses the outlined button appearance. `variant="card"` keeps the same canvas and places the body on a 6 px inset, borderless medium-radius content surface. Its 14 px heading uses heading weight and a 22 px line box, aligned with the content text start edge; the close target remains 8 px inside the content card's right edge while footer actions align with the card. The header uses a 12 px top inset, followed by a single 12 px section gap before the content surface and a 10 px gap from the content card to footer buttons. Footer top padding is zero to avoid doubling that gap; the bottom inset is 10 px, and the heading text is offset 2 px downward within its text column. Body padding independently controls the distance from content to the card edge. The 24 px close target contains a 16 px icon in the body text color, with a transparent resting background, a deeper standard neutral hover background and the small radius (6 px by default). Drawer retains section dividers and a muted footer by default; `divided={false}` groups its content with spacing. Their heading icons share a neutral circular base. Confirm is an API-only decision prompt: a compact 420 px surface, spacing-based sections, a bare semantic glyph beside the explanation and no background base or section dividers. Its heading starts at the content edge, independently of the body icon. Popconfirm and Notification use a bare semantic glyph aligned with the title line. Modal and Drawer footers share 12 px vertical insets; spacing-only dialog and Confirm footers use 12 px below their actions. Titles and supporting descriptions share an independent text column. The close action remains on the inline end. Body content scrolls without moving the heading or footer. Borders and surfaces derive from the current light/dark region, including custom palettes and density.

Date, time and range picker panels share `panelVariant="card"` with the Modal card treatment. The popup is a muted canvas; the calendar, time columns, paired panels and preset region use inset content surfaces with the medium radius. Picker footers lose their divider and tinted strip so they sit directly on the canvas, aligned with the content surface. Keep the same hierarchy in light, dark, RTL and narrow layouts.

The full Calendar uses an editorial, borderless grid. A large localized month name carries the heading, with the year as a lighter companion and Today plus paired navigation controls at the trailing edge. Date, month and year views use open 7-, 4- and 3-column layouts; date cells never draw individual frames. Selection fills the whole date cell with a quiet primary tint and marks the numeral with a solid circular label. Today uses primary-colored text and a small dot instead of an outline. `cellRender` content sits below the numeral in one truncated line. Compact calendars keep a 32px borderless date grid without changing their surrounding picker structure.

Card no longer exposes `hoverable` or adds hover lift; it keeps a subtle resting shadow offset downward, and `bordered` remains available. Card `size` offers small, default and large layouts: body padding defaults to 16 / 20 / 24 px, heading insets to 12 / 16 / 20 px and title text to 13 / 14 / 16 px. Embedded Tabs follow the Card size unless explicitly overridden; child controls keep their own sizes. Card headings use `headingWeight` (600 by default) and equal vertical insets; the body does not add a second inset below an undivided header. Card always groups the heading, body and footer with spacing; it has no public `divided` mode. `variant="inset"` keeps the heading on a muted canvas and places the cover, tabs, body and footer on a surface inset by 6 px. The inset radius is derived from the outer radius, and content padding compensates for the inset so headings, tab labels and body content share a reading edge. Checkbox/Radio card choices have one full clickable label, a neutral icon base, a title/description column and a trailing native control. Groups may arrange these as a responsive grid or one list with shared borders and row separators. Selected borders use the primary color without gradients or lifting. Status tags are non-interactive, and supporting text is an accessible description rather than part of the choice name. Neutral Alert surfaces preserve semantic icon colors and announcement roles.

Card can integrate top line tabs through its `tabs` configuration. With a heading, navigation sits below the title and description without an intervening divider; without a heading, tabs fill the entire heading height with vertically centered labels and Card actions move to the trailing edge. Replacement headings derive their minimum height from the Card title line and symmetric heading insets, respect larger explicit tab sizes, and have no top-only outer padding. One full-width divider runs under the entire tab bar, including its actions; the selected underline overlays that divider so its thickness matches standalone line tabs. Tab labels and panels align with the Card content edge, panel insets and header surfaces inherit Card tokens, and tab size follows Card size unless explicitly set. The footer keeps the same spacing-based treatment. Reuse Tabs navigation, overflow, content retention and animation rather than creating a second tab state system; loading replaces panel content while navigation remains mounted.

CardTitle reuses Card title typography outside a Card, without adding a surface or padding. Its small, default and large sizes match Card titles (13 / 14 / 16 px at the default base font size); both Card and CardTitle default to an h3 heading, so callers should not specify a level unless the surrounding document outline requires it. `description` sits beneath the heading and `extra` at its trailing edge, matching the Card heading area. Both use the regional font family, base font size and heading weight. Card owns its internal title size and does not consume standalone CardTitle default props; user-supplied CardTitle elements still receive their regional defaults.

FileList uses one shared frame and row separators for text and thumbnail lists. Visuals, file information and actions occupy separate columns; names truncate within their column, while type and optional size remain secondary. Upload state, progress and errors belong to the information column. Preview buttons, download links, removal and Upload actions share square geometry. Picture cards keep a stable preview ratio and align their actions at the bottom. Missing sizes leave no empty placeholder, failed thumbnails retain a type icon, and asynchronous removal feedback stays with its file. No row shadow or hover lift is applied.

ConfigProvider remains the configuration entry. Base colors, radius and height derive related geometry; advanced `dividerColor`, component `borderColor`, `headerBackground` and `footerBackground` provide selective overrides. CSS variables are consumption points for application styling. Filled actions and checkmarks remain solid colors, and single-line controls keep the 34px base height.

Buttons expose solid, outline and link appearances; outline is the default. Outlined actions use a content surface, body text, a visible neutral border and one subtle resting shadow. Hover keeps the full resting appearance, while press deepens only the border to the semantic active color without changing text, background or shadow. Danger outlines use readable danger ink for the label, the danger base color for the resting border and `danger-active` while pressed. Link actions use theme-colored text with no border, padding or control-height minimum; hover keeps the resting color, press changes only their color, and activation has no wave. Explicit component state overrides retain precedence. Alerts use one neutral surface with semantic icon colors. Result icons sit on the same muted circular base for every status. Table surfaces use the same base radius as buttons with a softened frame and the Card resting shadow. Tables use 12 px bold, slightly muted column headers and divider-colored separators, and fill their container before horizontal overflow; a minimum width remains a lower bound. Scrollbar tracks overlay content and appear on hover, scroll or keyboard focus; dragging must neither steal input focus nor add a pointer focus outline.

Development migration: Button now exposes `solid`, `outline` and `link`; `outline` is the default, and the former public `ghost` and `soft` appearances are removed. Replace secondary soft actions by omitting `variant`, and keep borderless composite controls private to their owning components. Remove Alert `variant` props. Comfortable controls now derive 28 / 34 / 40 px sizes; compact controls use a 30 px base. Set `theme.controlHeight` explicitly when an application needs to retain its former sizing. Content surfaces move from the large to the new medium radius (`borderRadiusMd` / `--leaf-radius-md`) and drop their previous default shadow; Card and Table keep only a subtle resting shadow offset downward. The default base font moves to 14 px / 20 px, small text to 13 px / 18 px (`fontSize - 1px`) and large text to 16 px / 22 px (`fontSize + 2px`); Card and CardTitle sizes become 13 / 14 / 16 px, and tags and section labels keep a 12 px minimum. `lineHeight` now accepts `number | string` and defaults to 20 px. Numbers from greater than 0 through 4 keep the former multiplier meaning (`1.6` produces a 22.4 px line box at the default font size); other numbers are pixels, and strings are CSS lengths. Card and CardTitle line boxes are 18 / 20 / 22 px, and step indicators are at least 24 px (28 px at the large size). Button inline padding derives from its actual height (0.42 times the height, 14.28 px at 34 px), with explicit component padding taking precedence for every size; component titles other than Card use `fontWeight` instead of `headingWeight`; rich choice legends use section labels; replace controlled `Confirm` / `ConfirmProps` with `useConfirm().confirm(options)` / `ConfirmOptions`, and move rich confirmation flows to Modal; Confirm retains a bare body icon; tags use borderless fills, the small radius, weight 500 and no configurable weight; replace Tag `variant="outline"` with the default `soft` appearance; popups use `shadow-md`; Pagination uses outlined page buttons by default. Include these compatibility changes in the next release's migration notes.

Acceptance uses keyboard behavior, geometry assertions, axe, SSR, build/package checks and manual inspection in both themes and densities. Screenshot baseline comparisons are deliberately deferred. See `IMPLEMENTATION-BATCHES.md` and `packages/react/ACCESSIBILITY.md` for evidence and manual coverage limits.
