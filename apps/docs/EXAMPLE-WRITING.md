# 文档示例编写规则

本文件是 [AGENTS.md](AGENTS.md) 引用的必读约定，适用于主站组件和指南示例。页面结构、内容取舍与 API 说明见 [使用文档编写规范](DOCUMENT-WRITING.md)，本文件只维护示例的展示与源码规则。

## 内容范围

每个示例回答一个主要问题，一组对比只改变一个主要维度。基础用法先展示组件默认外观，再说明尺寸、状态、受控值或必要的交互；不把尺寸、禁用、错误、主题和业务操作混成一张能力展板。能力确实需要组合时，只保留完成该操作必需的状态与控件。

主站不编写完整的项目管理、权限工作台、十字段设置页或多步骤业务流程。复杂组合、装饰性封面和业务页面属于将来的独立 example 站点。展示 API 必需的本地状态、提交、重置和异步处理可以保留，但尽量使用最少的字段与数据。

## 容器与对齐

- 示例容器 `ComponentExample` 默认在预览区水平、垂直居中，内容宽度为 **480px**；窄屏自动限制到可用宽度。用 `width={360}`、`width={600}` 或 `width="100%"` 调整单个示例。
- **外层居中，内层按用途对齐**：外层容器控制整组示例在预览区的位置；内部的文字、字段和对比项按下表排列。不能把“容器居中”理解为所有文字和控件都居中，也不能在每个示例里另设一套外层对齐。
- 展示用宽度通过 MDX 的 `ComponentExample` 配置，外围居中和留白由容器统一负责，不重复写进可复制示例源码。容器只控制外部展示，不改写组件圆角、字号、内边距、颜色和状态。
- 同页同类示例沿用相同宽度，不因某个例子的内容较短就单独收窄。自然宽度与整宽内容按下表选择；其他宽度例外必须由展示能力决定，而不是逐例调到“看起来好看”。

### 按展示目的选择布局

| 展示类型 | 统一布局 | 文字与名称 |
| --- | --- | --- |
| 单个紧凑组件 | 单按钮、标签、图标等保持自然宽度，使用 `width="fit-content"` 让整组居中，不拉伸组件。 | 能从组件内容辨认时不另加名称。 |
| 紧凑组件对比 | 每行一组，组件横向排列并垂直居中，空间不足时换行；有分类名称时左侧为名称、右侧为组件，同组左边界一致。 | 需要分类时在左侧使用简短名称；不要把分类名称写进按钮文字来伪装成组件差异。 |
| 宽组件对比 | 输入框、选择器、卡片等按项纵向排列，每项名称在上、组件在下，均左对齐；默认不为了塞进一行缩窄组件。 | 各项都使用相同的上方名称位置；确需并列比较时用 Grid，仍保持名称在上。 |
| 表单 | 使用 Form / FormField，单个示例及同页同类表单统一标签方向与字段起始位置。 | 字段名称由 FormField 提供，不另造左右标签；只有演示标签布局本身时才对比不同方向。 |
| 表格、列表与其他宽内容 | 在居中的内容容器内铺满可用宽度；默认宽度不足时配置更宽容器或 `width="100%"`，不把整体改成靠预览区左边缘。 | 名称和说明沿内容左边界，不为了外层居中而居中文字。 |
| 浮层或服务触发 | 只有一个触发按钮时使用 `width="fit-content"`，保持自然宽度并居中；多个触发器按紧凑组件对比组织。 | 用按钮文案说明动作，不额外堆放一份相同说明。 |

同一页面的同类对比必须采用同一布局，不混用名称在上、名称在左和名称作为说明段落。数据表格、时间线等组件自身的布局不受此表改写；正在演示布局能力时，可以有明确命名的对比例外。

### 文字角色

| 角色 | 放置与表达方式 |
| --- | --- |
| 示例目的、配置方法与限制 | 写在 MDX 标题或示例前正文，不把长说明塞进预览。`ComponentExample.title` 用于示例命名与可访问名称，不代替可见的章节标题。 |
| 尺寸、状态、样式等对比名称 | 使用 Text，按展示类型固定在左侧或上方；同组使用相同的次要文字样式，不逐项改颜色、字号或字重。 |
| 表单字段名称、帮助与错误 | 由 Form / FormField 统一承载并关联控件；对比名称不能替代控件必需的可访问名称。 |
| 操作结果、当前值与反馈 | 只有解释交互所必需时才展示，固定在相关控件下方；使用 Text / Paragraph 或对应反馈组件，不额外包一层装饰面板。 |
| 组件自身内容 | 保留在组件内，如按钮动作、选项名称、卡片标题；不拿它代替外部的示例说明。 |

名称使用“默认”“禁用”“小 / 中 / 大”等可辨认短语；不要给每项重复加“示例”“效果”。不为统一布局补充无意义的名称，已有字段名称或组件内容足以区分时不重复标注。

## 源码布局与样式

- 组件排列使用公开的 `Flex`、`Space` 和 `Grid`。主轴对齐和换行使用 Flex；等间距组合使用 Space；分栏使用 Grid。
- 表单标签、帮助信息和错误使用 `Form` / `FormField`，说明文字使用 `Text` / `Paragraph`，面板使用 `Card`。不手写相同的标签、面板或文字样式。
- 使用公开布局参数表达必要的分组和间距，同类示例复用一致的间距，不靠空格、空行、空元素、任意 margin 或定位偏移凑对齐。不为预览整齐而强改组件的真实默认宽高。
- 主站示例不依赖 Tailwind 工具类、文档专属类名或隐藏样式文件。复制示例后，只安装 Leaf UI 及源码明确导入的依赖即可使用组件。
- 只在表达当前能力必需时保留少量原生 `style`，例如滚动区域高度、浮层定位、动态颜色或实际演示的尺寸覆盖。不要用 CSS 装饰一个复杂场景来替代基础用法；需要大量 CSS 的内容移出主站。
- 不通过源码过滤器删除布局或样式来制造简洁代码。预览组件与展示、复制、AI 导出的代码必须对应同一实现。
- 不用只存在于文档站的布局 helper 隐藏示例必需结构。需要复用时优先使用公开布局组件；如确需本地 helper，展示、复制与 AI 导出必须包含其实现或可解析源码，不能让读者依赖未提供的代码。

## 窄屏与语言变化

- 紧凑组件组优先换行，不缩小字号或点击区域；有左侧分类名称的对比行在放不下时统一改为名称在上、组件在下，不逐项选择不同方向。
- 宽组件与表单不超过可用宽度；并列对比在窄屏按原顺序变为单列，名称仍跟随对应组件。数据表格等本来需要横向滚动的内容保留组件自身滚动，不让整个文档页面横向溢出。
- 不用固定高度裁掉帮助文字、操作结果或英文长标签；换行后保持名称与组件的关联。中英文使用相同的布局策略，不能为一种语言单独改成另一套展示形式。

## 颜色与主题示例

基础示例不覆盖默认配色。演示主题定制时使用公开 ConfigProvider JS 配置，保留可见的输入名称与实际配置代码；不手写派生色板、不监听 DOM 回算颜色，也不依赖文档站私有皮肤。实底前景规则见 [颜色系统：角色映射与选阶](../../COLOR-SYSTEM.md#角色映射与选阶)。颜色页的六组全局色带、基色值与可编辑示例范围见 [颜色系统规范](../../COLOR-SYSTEM.md#自动约束与验收)，内部算法和迁移债务不写进使用者示例。

## 源码与中英文

中文示例位于 `src/examples/<component>/`，英文镜像位于 `src/examples/en/<component>/`。MDX 预览导入该组件，代码围栏的 `file` 引用相同的源码。以下是指南等非结构化页面的通用写法；组件页使用[固定模板](DOCUMENT-WRITING.md#最小编写模板)，以 `exampleId` 代替 `title`：

````mdx
import { ComponentExample } from '../../src/components/component-example';
import { InputBasic } from '../../src/examples/input/basic';

<ComponentExample title="基础输入" preview={<InputBasic />} width={360} fileName="basic.tsx">

```tsx lineNumbers file="../../src/examples/input/basic.tsx"
```

</ComponentExample>
````

不要再维护一份独立手抄的展示代码。语言专用的 `english` 参数和翻译判断由 `scripts/example-source.mjs` 消除；真实的语言切换状态继续保留。显示、复制和 AI Markdown 导出使用同样的处理。

[结构化组件页](DOCUMENT-WRITING.md#组件页固定结构)使用 `exampleId="basic"` 等稳定身份，不重复填写 `title`；标题由构建插件从所属 Markdown 标题注入。预览、宽度、源码 `file` 的写法不变。每个预览示例必须对应一个具名导入的自闭合预览和一份同源代码围栏；预览只允许省略参数或传入字面量布尔 `english`。其他动态参数、插入子内容或重复属性会报错，不会被静默丢弃。构建时检查预览与源码对应关系。无运行预览的完整接入配方及其 ID 写法见组件页规范，不另建内容副本。

组件新增或 API 改变时，同步中英文页面、公共类型、侧边栏、总览元数据与 SVG 缩略图。API 默认值必须来自实际实现。

## 验收

按 [质量验收的影响分级](../../packages/react/QUALITY.md#测试边界与日常执行) 选择检查，不为纯文案或预览容器修改运行无关库构建。涉及 TSX 时执行相关格式和文档类型检查；最终态文档构建一次。新增公开组件仍需检查根入口、子路径、声明、自动样式和 SSR。

布局调整必须在浏览器验证中文、英文、桌面与窄屏、深浅外观及主题切换。检查预览溢出、控件交互、源码展开/收起和复制的一致性；仅构建通过不能报告视觉验收完成。

浮层示例还须实际展开并检查内部标题、文字、字段与操作是否完整可见；页面没有横向溢出不代表浮层内部没有裁切。表单等宽内容应按需要配置公开的浮层宽度，不依赖触发按钮或内容的固有宽度碰巧撑开。

验收时同时检查整页同类示例的宽度、内外层对齐、名称位置、文字角色与分组间距，不只截取某一个预览。确认每个示例只有一个主要目的，窄屏和英文长文本下关联清楚，复制源码后不依赖文档站隐藏布局。新增规则不等于存量示例已经符合，不得据此宣称全站已统一。

文档容器缺陷的长期回归使用真实生产页面，不用独立组件 fixture 代替。持久测试入口和并行端口 / 报告隔离统一见 [浏览器运行规则](../../packages/react/QUALITY.md#浏览器运行与报告隔离)，不要再维护每任务一份的临时配置。
