# 使用文档编写规范

本文件由 [AGENTS.md](AGENTS.md) 引入，适用于主站组件页、指南与 API 参考的新增和修改。内容取舍、页面结构与 API 说明以本文件为准；预览布局和示例源码遵循 [示例编写规则](EXAMPLE-WRITING.md)，生成与站点实现遵循 [维护说明](MAINTENANCE.md)。本文件是仓库维护规范，不放入发布目录 `docs/`。

## 面向使用者

文档帮助读者判断“是否适用、怎样使用、哪些行为需要自己处理”，不承担组件实现说明、设计验收或修复记录的职责。

每段说明至少完成一件事：帮助选择组件或用法、说明必要配置、解释值和事件、指出会影响接入结果的限制。删掉后不影响这些判断的内容，默认不写。

| 内容 | 处理方式 |
| --- | --- |
| 值的格式、受控与非受控、清除结果、事件时机、异步与重置责任 | 保留，放在对应示例或 API 附近。 |
| 组件选择、易混能力的区别、真实限制与必要的可访问名称 | 简短说明，给出可执行的用法或替代方案。 |
| 默认尺寸清单、内部间距、阴影层级、圆角计算、内部组件与颜色角色 | 不写入常规使用说明；确实影响配置的公开尺寸和 token 放在对应 API 参考。 |
| 防抖动、修复溢出、保证对齐等实现动机，回归记录、迁移债务 | 留在实现说明、测试或仓库维护记录，不写成使用者的操作步骤。 |
| 代码中一眼可见的操作、API 表已有的完整解释 | 不再逐句复述；正文只补代码和表格不能直接表达的语义。 |
| 跨组件通用的主题、表单、浮层配置教程 | 链接到唯一归属页；当前组件只补差异和特有约束。 |

例如，不写“HEX、RGB、HSL 的默认宽度分别为……，避免透明度小数变化时控件和浮层抖动”。基础用法无需这段说明；只有实际演示宽度配置时，才写“通过 `style.width` 设置控件宽度”。公开 `width` 参数的默认值仍须在 API 中准确列出，不能以精简为由删除必要信息。

## 页面组织

组件使用页遵循下一节的固定结构。基础示例先展示默认外观和最常见操作，普通示例按常用到进阶排列，不按属性清单机械展开。重要约束紧邻对应示例，不藏在页尾长段落里；API 放在所有用法之后。

指南按实际接入步骤递进，参考页按查询对象分组，不机械套用组件页模板。跨页复用同一知识点时引用原页面，不复制成多份解释。

`guide/design-standards` 是页面组合与公开基础标尺的唯一使用者指南：可以集中说明字号 / 行高、字重、间距、尺寸、圆角、阴影和颜色角色，必须给出真实组件用法或公开 CSS 变量，并区分默认参考与用户覆盖。默认数值核对组件源码的 `styles/tokens.scss`、`density.ts`、`theme.ts` 和实际组件；不另造一套整数标题字号、固定色板或 AI 专用正文。颜色说明使用角色，不要求页面复制默认 HEX；组件页和 Skill 只链接 / 查询此指南，不复制标尺表。主题参数的完整定义仍归属生成的 API 参考，颜色算法和内部几何仍归属仓库维护规范。

- 示例标题直接命名能力，如“搜索”“限制选择数量”，不使用“能力展示”“完整演示”等模糊标题。
- 示例按使用频率排序，进阶示例用标题和说明指出适用条件；不为每个属性新增一个示例，也不为了凑数量重复基础用法。
- 同一行为只在一个主要位置完整解释。示例正文说明怎么使用，API 表提供准确的属性查询，不再在末尾“使用说明”中复写一遍。
- 不单独堆放只有类型导入代码、没有使用语境的“类型”“扩展类型”章节；类型放在对应 API 附近，复杂类型通过链接查询。
- 调整存量页时检查标题锚点、站内链接与 API 生成器的定位，避免重排造成断链。规范建立不代表存量页面已完成整改。

## 组件页固定结构

所有具有独立 API 的组件使用页采用以下结构；新建或修改页面时不得另建一套组织方式：

1. 一个一级标题：组件名称；随后用正文简短介绍用途。
2. `基础用法 / Basic usage` 二级标题：说明和一个完整基础示例。
3. `示例 / Examples` 二级标题：每个示例用三级标题，包含说明、代码及必要的后续注意事项；示例内部更细的标题从四级开始。
4. `API` 二级标题：每个 API 用三级标题，包含名称、介绍和参数表。主组件自身的 API 必须第一，之后才是子组件、Hook 和关联类型；不能按字母排序把 MenuItem 放在 Menu 前面。API 之后不再追加用法区域。

`components/index` 是组件目录，`components/icons` 是跨组件的图标接入指南，不套用组件模板。`components/empty` 只保留兼容迁移说明，其 API 唯一归属于 Result 页，不复制一份表格。指南及 `api/` 参考页仍按其用途组织，不能为满足组件结构而伪造示例或 API。

### 身份与边界

页面在导入之后、一级标题之前声明静态元信息，例如 `export const leafDoc = { component: 'Menu', primaryApi: 'MenuProps' };`。`component` 使用页面真实主入口，`primaryApi` 使用其公开 Props 类型；以服务或 Hook 为主的页面可声明真实服务或 Hook 身份，不能为了排序而编造不存在的类型。元信息只记录身份，不复制标题、说明或代码，不使用计算属性、函数调用或对象展开。导入和元信息不得穿插在正文中。

每个区域前分别写独立的 MDX 注释 `{/* leaf:section basic */}`、`{/* leaf:section examples */}`、`{/* leaf:section api */}`，顺序固定且只能出现一次。区域语义由标记确定，不通过匹配中文标题猜测。每个示例从三级标题开始，到下一个同级标题或 API 区域结束；后续说明和四级小节仍属于本示例。安装前提属于简介或基础用法，不得因迁移到结构化数据而被删除。

每个示例的 `ComponentExample` 声明稳定的 `exampleId`；基础用法固定为 `basic`，其他 ID 使用小写英文、数字和连字符，页内唯一，不因翻译、标题或顺序变化而改变。中英文使用相同的 API 和示例身份、顺序。标题只写在 Markdown 标题中，不再重复填写 `title`；源码仍按[示例规则](EXAMPLE-WRITING.md#源码与中英文)引用，不手抄。普通示例序号由文档顺序自动生成，从 1 开始，不计入基础用法；序号随排序变化，持久引用使用 ID。

确实不适合运行预览的接入配方（例如外部表单库集成）可以保留原有完整代码围栏，在所属三级标题下写独立注释 `{/* leaf:example react-hook-form */}` 作为稳定 ID。每个此类区块必须有说明和代码，不能再与 `ComponentExample` 混用。普通示例可以为零，不为了填满区域重复示例。只有注意事项、没有代码的内容应归入相关示例、基础用法或 API 介绍，不伪装成独立示例。

### API 与内容保留

每个 API 先简短说明它对应的组件、参数或返回对象，再放生成表格；不要只重复标题，也不要把使用者需了解的原有介绍替换为通用套话。对象属性使用真实三列或四列表格；纯函数签名、联合类型或类型别名可保留签名及说明，不为了凑表格捏造属性。公共 API 表格只能由同步脚本更新，结构迁移可以整体移动包含介绍和表格的完整 API 区块，不能手工改表格单元格。

迁移时逐块保留原有段落、列表、代码、前提和限制，只改变归属与层级。删除分组标题或重命名基础标题时保留原锚点；同名标题降级后也要检查锚点。代码里的伪标题和伪标记不能影响区域切分。引用式链接必须随提取区块保留所需定义；未知 MDX、无法解析的动态内容、不同源的预览与围栏必须报错，不能静默省略。

### 查询与验收

组件详情查询提供完整基础用法、完整 API 和示例名称列表；示例详情按序号、ID 或标题提取完整区块，不丢弃代码前后的说明，不重新编写摘要。主 API 使用现有标题时允许保留 `Select API` 这类名称，避免改变既有锚点；身份由 `primaryApi` 明确声明。迁移被移除的分组标题时保留原锚点。

结构标记只承担机器定位；展示内容仍然只有一份，不为 CLI、Skill 或 MCP 手写另一套组件手册。结构化 JSON 由文档和示例源码生成，禁止手改或把生成产物当成新的内容源。生成、解析及检查入口见[维护说明](MAINTENANCE.md#结构化组件文档)。

新增和迁移页面须通过结构解析、双语身份与顺序检查、API 主入口顺序检查以及完整代码提取测试，并检查相关链接与旧锚点。构建失败时修正文档或显式补充解析规则，不关闭检查。网页效果、交互及按需排障遵循[质量规则](../../packages/react/QUALITY.md#当前验收规则)，不要求逐页浏览器回归，也不按主题或屏宽重复检查相同的导出内容。

## 说明与措辞

- 参数名、值、事件名和代码表达式使用行内代码；正文使用使用者能理解的语言，不直接暴露 `ink`、绘制责任、私有 CSS 类等内部术语。
- 说明“配置后会怎样”以及“应用需要做什么”，不写“优雅”“强大”“灵活”等评价，不反复宣称默认就应该具备的稳定、对齐和可读性。
- 不把可从预览直接观察到的间距、留白、按钮排列写成长篇外观说明。滚动范围、状态保留等会影响操作的结果可以保留，内部实现方式不必解释。
- 交互与可访问性说明只保留必要责任和组件特有行为，如提供名称、特殊快捷键、焦点目标；不在每页重复原生控件的完整键盘教程。
- 注意事项具体说明条件、结果和处理方法，不写笼统的“请按需配置”“注意性能”。可能导致数据错误或操作失败的限制不能因精简被删除。
- 中文与英文保持相同的信息层级、行为描述和示例覆盖，不只翻译新增的一句话而遗漏相邻重复内容。

## API 信息质量

- 类型、默认值、是否必填和行为必须对应当前公开源码，不依据旧文档、示例表现或类型名称推测。
- `value` 与 `defaultValue` 分别解释受控值与非受控初始值；区分内置默认值、动态默认值和示例传入值，不能把示例值写成默认值。
- 事件说明包含必要的返回值、清除值、触发时机，以及同步 / 异步责任；多种模式的返回结果分别说清楚，不能只描述单选或某一模式。
- 常用核心参数优先于低频的样式、挂载容器等配置，相关参数相邻。生成顺序不合理时改生成器的组织逻辑，不手工重排生成表；生成流程统一见 [维护说明](MAINTENANCE.md#api-与-ai-文档)。
- 正文、示例和 API 表对自动行为与默认值使用同一口径。例如自动启用虚拟滚动时，不写成使用者必须手动开启。
- 不为显示某个公共类型而孤立追加类型表；解释它与哪个参数关联，或从对应 API 链接到其唯一参考位置。共享类型不在各组件页重复维护完整表格。

- [ ] 没有内部尺寸清单、修复动机、实现术语或无操作价值的外观描述。
- [ ] 同一说明没有在示例前、API 后和页尾反复展开；常用、进阶与 API 层次清楚。
- [ ] 默认值、事件、自动行为与当前源码一致，相关类型有明确引用关系。
- [ ] 示例符合 [示例编写规则](EXAMPLE-WRITING.md)，中英文结构与信息一致。
- [ ] 没有孤立的表格分隔符、占位内容、失效链接或失效锚点。
