# 界面设计与组合

使用 Leaf UI 创建工具、管理和数据密集页面时，以中性表面构建层次，保留轻微实体感：控件紧凑，容器留白清楚，标题克制，让内容和数据成为主角。已有项目有明确设计体系时，先保持其一致性，不把所有页面改成同一个后台模板。

本页说明怎样组合组件，以及自定义页面布局怎样沿用库的标尺。数值是未覆盖主题时的默认参考，不是要求页面重新写死的 CSS；组件参数、区域密度和用户主题覆盖优先。完整配置见[定制主题](/guide/theming)与[主题变量](/api/theme-tokens)。

## 从组件理解视觉语言

| 组件 | 当前外观 | 页面组合方式 |
| --- | --- | --- |
| [Menu](/components/menu) | 默认 `raised`，柔和底板上的选中项使用独立内容面、细边框和轻投影。 | 导航沿用选中表面；不再叠加另一条高亮或大面积品牌色背景。`neutral` 和 `primary` 是其他明确的外观选择。 |
| [Button](/components/button) | 默认 `outline`，中性内容面和边框，带轻微静止阴影。 | 普通操作保持中性，关键操作才使用 `solid`；不让所有按钮同时争抢注意力。 |
| [Card](/components/card) | `variant="layered"` 用底板承载小号弱标题，内层内容面承载正文。Card 本身默认仍是 `default`。 | 独立任务分区需要标题与内容分层时使用 `layered`；此时不显示 `description`，重要说明放在正文或独立 CardTitle 中。 |
| [DataTable](/components/table) | 默认 `layered`，弱化表头与内层数据表面延续分层 Card 的关系。 | 主要数据区域直接放置表格和工具栏；通常不再外包一层同样的分层 Card。确需嵌入已有内容面时考虑 `simple`。 |

“底板”和“内容面”是角色，不是固定浅灰和纯白。用户改变表面色或切换深色外观后，分组关系仍应保留。选中状态沿用组件自身的表面、勾选、边框或指示，不在页面层强制统一成“永远没有背景”或另一套主题色高亮。

## 组织页面

- 先确定页面标题、任务分区与数据区域，再选容器。页面标题承担主要层级，分区标题不要全部做成大号强标题；相关操作靠近对应内容。
- 导航、页头、工具栏和内容职责分开。导航用 Menu；普通并列内容用 Flex / Grid；独立任务区用 Card；数据区优先直接用 DataTable。
- 用间距区分相关性，不为每段文字或每行字段增加卡片、分割线与阴影。页面级操作和行内操作分开，一个任务区优先只强调一个主要动作。
- 控件紧凑不等于内容拥挤。同一组间距一致，分区之间比组内更宽；长标签允许换行，不缩小字体和点击区域硬塞。

## 字号与字重

| 文字角色 | 默认字号 / 行高 | 使用方式 |
| --- | --- | --- |
| 正文 | 14px / 20px | `--leaf-font-size` / `--leaf-line-height`；正文常规字重 400。 |
| 次要、小号文字 | 13px / 18px | `--leaf-font-size-sm` / `--leaf-line-height-sm`。`Text tone="muted"` 只改变颜色，不自动缩小字号。 |
| 大号文字 | 16px / 22px | `--leaf-font-size-lg` / `--leaf-line-height-lg`。不要把每个标签都放大。 |
| 控件与普通分区标题 | 默认字重 500 | `--leaf-font-weight`；使用 Button、CardTitle 等现有组件，不额外覆盖为 600。 |
| 强调文字与醒目标题 | 默认字重 700 | `Text strong` 或标题组件；标题使用 `--leaf-heading-weight`，不要把所有正文加粗。 |

优先用 Typography、Text、Paragraph、CardTitle 和 Title。自定义页面根节点应继承 `--leaf-font-family`、`--leaf-font-size` 与 `--leaf-line-height`；ConfigProvider 提供变量，不会自动把任意原生文本变成库的排版。默认字体栈以 Inter 开始并包含系统与中文回退，配置 `theme.fontFamily` 后继续继承，不另引入展示字体。

CardTitle 的 `sm / md / lg` 默认分别为 14/20、16/22、18/24px，大号使用标题字重。Title 的 `level={1..6}` 同时决定语义与默认大小：依次为基础字号的 2.3、1.85、1.5、1.25、1.1、1 倍，行高 1.3；它不是固定的整数像素表。选择真实的标题层级，不用较大的标题级别充当普通标签。

## 间距与密度

| 间距变量 | 宽松默认 | 紧凑默认 | 常见用途 |
| --- | --- | --- | --- |
| `--leaf-spacing-xs` | 4px | 3px | 标题与短说明等紧密关联内容。 |
| `--leaf-spacing-sm` | 8px | 6px | 相邻操作、紧凑控件组。 |
| `--leaf-spacing-md` | 16px | 12px | 同一内容区内的分组。 |
| `--leaf-spacing-lg` | 24px | 18px | 独立内容分区、页面留白。 |
| `--leaf-spacing-xl` | 32px | 24px | 更大的区块分隔，避免逐项随意增大。 |

基础间距 `--leaf-spacing` 默认宽松 8px、紧凑 6px，上表依次为其 0.5、1、2、3、4 倍。用 `ConfigProvider density="compact"` 切换区域密度，或通过 `theme.spacing` 配置基础间距；显式主题和组件参数优先。紧凑密度不缩小正文。

Flex 的 `gap="sm|md|lg"` 与 Space 的 `size="sm|md|lg"` 直接读取对应变量。Grid 的 `gap` 不解析这些名称，使用 `gap="var(--leaf-spacing-md)"`；需要 xs / xl 时同样传 CSS 变量。不要给每个区块各写一组近似的像素间距。

## 尺寸、圆角与阴影

| 几何角色 | 宽松默认 | 紧凑默认 | 使用方式 |
| --- | --- | --- | --- |
| 控件 `sm / md / lg` 高度 | 28 / 34 / 40px | 24 / 30 / 36px | `size` 选择局部尺寸；自定义布局读取 `--leaf-control-height-sm`、`--leaf-control-height`、`--leaf-control-height-lg`。 |
| 表单行 / 标签间距 | 16 / 6px | 12 / 4px | 交给 Form / FormField；对应 `--leaf-density-form-gap` / `--leaf-density-label-gap`。 |
| 列表行纵向内边距 | 12px | 8px | 由组件密度处理；不要设成固定行高裁切多行内容。 |
| 浮层选项最小高度 | 30px | 26px | 跟随控件高度，保留组件键盘与点击区域。 |
| 对话框块向 / 行向内边距 | 20 / 24px | 16 / 20px | 沿用 Modal / Drawer 的现有结构，不为页面另造一套弹窗间距。 |

尺寸和密度是两个维度：同一行控件使用一致 `size`；通过 ConfigProvider 统一密度，不逐个缩放。触屏操作应提供更宽松的目标，不因套用紧凑表格而缩小所有按钮。

圆角使用 `--leaf-radius-sm`、`--leaf-radius`、`--leaf-radius-md`、`--leaf-radius-lg`，默认为 4 / 8 / 12 / 16px，随基础圆角按 0.5 / 1 / 1.5 / 2 派生。通常由组件处理内外嵌套，不手工覆盖内部 `.leaf-*` 圆角。

阴影使用库提供的 `--leaf-shadow-xs`、`--leaf-shadow-sm`、`--leaf-shadow-md`、`--leaf-shadow-lg`：描边按钮和默认 Card 的静止反馈最轻，分层 Card / Table 的内层内容使用 `shadow-sm`，浮层使用更高层级。优先使用组件默认值，不在容器外重复添加阴影；悬停不抬升、不放大、不切换阴影等级。需要覆盖时通过主题配置，保留用户 `controlShadow` / `surfaceShadow` 设置。

Input、InputNumber、InputSearch、Select、AutoComplete、Cascader、TreeSelect 和单值选择器默认宽 240px，选值后不改变宽度。日期区间为 300px，日期时间区间为 380px；较长格式适当加宽。窄容器中自动收缩，FormField 内默认铺满；`style.width` 可显式覆盖，Textarea 保持默认铺满。页面布局不能依赖字段永远等于这些默认宽度。

## 颜色使用角色，不使用固定色值

| 页面用途 | 读取的主题变量 / 组件用法 |
| --- | --- |
| 正文、说明 | `--leaf-color-text`、`--leaf-color-text-muted`；Text / Paragraph 的 `tone`。不要给整段正文加 opacity 代替文字角色。 |
| 内容面、柔和底板、浮起表面 | `--leaf-color-surface`、`--leaf-color-surface-muted`、`--leaf-color-surface-raised`。不把“白色卡片”写成固定白色。 |
| 外框、交互边框、分割线 | `--leaf-color-border`、`--leaf-color-border-hover`、`--leaf-color-divider`；不把分割线全部改成外框色。 |
| 普通表面上的主题色文字 | `--leaf-color-primary-ink`，或 `Text tone="primary"` / Link；不直接拿主题基色作小字颜色。 |
| 主题色实底与其文字 | `--leaf-color-primary` 配 `--leaf-color-on-primary`，优先使用 `Button variant="solid"`，不要自行指定白字。 |
| 成功、警告、危险、信息 | 使用对应状态组件；自定义语义文字使用该 family 的 `*-ink`，浅底使用 `*-soft`，实底与 `on-*` 成对使用。状态色表达含义，不装饰普通分区。 |

更改品牌色用 `theme.primaryColor`；中性色、表面和其他语义色通过 `theme.tokens` 配置，例如 `neutralColor`、`surfaceColor`、`mutedSurfaceColor`、`dangerColor`。页面 CSS 只读取区域内的结果。不要用固定 HEX、中性色阶编号或手工混色复制默认配色，也不要给页面加覆盖用户配置的 `:root` 色板。

已有主题、嵌套 ConfigProvider 与深浅外观应继续生效。只覆盖基础 CSS 颜色变量不会重新运行 JS 派生算法，需要完整配色联动时更新 ConfigProvider 的配置。实底前景默认值不是对所有自定义颜色的可读性保证；更换基色后检查实际文字对比，必要时显式配置 `onPrimaryColor` 等前景。

自定义页面结构也读取同一套变量，样式放在应用自己的页面类中，而不是覆盖组件内部样式：

```css
.page-shell {
  min-width: 0;
  padding: var(--leaf-spacing-lg);
  background: var(--leaf-color-surface-muted);
  color: var(--leaf-color-text);
  font: 400 var(--leaf-font-size) / var(--leaf-line-height) var(--leaf-font-family);
}

.page-note {
  color: var(--leaf-color-text-muted);
  font-size: var(--leaf-font-size-sm);
  line-height: var(--leaf-line-height-sm);
}
```

将页面放在当前 ConfigProvider 的区域内。即使用户调整字号、基础间距或表面颜色，也不必重新定义这两组样式。

## 选择合适的外观

- 一般操作使用默认描边按钮，主要操作使用 `variant="solid"`；低强调局部操作可用 `text`，行内链接式操作可用 `link`，危险操作设置 `danger`。
- 不增加悬停抬起、按下缩小、彩色光晕或装饰渐变。保留组件自身的反馈，不在页面中重新设计每种状态。
- 输入和选择类字段聚焦或展开时使用主题色边框，不增加外圈；Textarea、Mentions 和 InputNumber 也遵循同一规则。错误、警告和禁用状态保留各自反馈；按钮保留中性键盘焦点轮廓。

## 主题与可访问性

通过 ConfigProvider 配置主题色、深浅外观与局部主题；用[颜色](/guide/colors)检查配色，逐项配置见[主题变量](/api/theme-tokens)。

窄屏时控件组优先换行，分栏按内容顺序转单列。表格可以在自身区域横向滚动，不让整个页面横向溢出。不要固定高度裁掉说明、英文长标签或焦点轮廓。

为字段提供标签，为纯图标按钮提供可访问名称。保留组件的键盘焦点和错误提示；动效遵循系统的减少动态效果偏好。

## 交付前检查

- 只用已有组件和公开 token，没有为相同职责增加另一套字号、间距、颜色和圆角。
- 分区来自任务与内容，没有无意义的卡片套卡片、重复阴影或所有标题都同样醒目。
- 用户主题和密度覆盖仍然生效；浅深外观、自定义品牌色和底板色下内容层级、文字对比清楚。
- 控件组窄屏可换行，数据只在自身区域滚动，加载、空态和失败状态仍有可理解的反馈。
- 使用与实际安装版本一致的 API；查询组件文档补齐行为，不把本指南当作完整 API 手册。
