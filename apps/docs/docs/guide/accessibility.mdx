# 可访问性验收

使用下面的工作台检查键盘、主题、密度、浮层和减少动态效果。组件提供基础语义；应用还需要为业务字段、图标按钮和复合控件补充合适的名称与说明。

<AccessibilityWorkbench />

| 检查 | 预期 |
| --- | --- |
| Tab / Shift+Tab | 顺序合理，焦点可见，禁用操作不进入顺序 |
| Enter / Space / 方向键 | 按钮可触发，选择和标签页可切换，Slider 可调整 |
| 弹窗 + 内部 Select | 焦点留在浮层体系内，Escape 先关闭内部浮层，再关闭弹窗 |
| 关闭浮层 | 焦点返回打开按钮，页面恢复可滚动与可操作 |
| 空字段 / 无效邮箱 | 显示字段错误，焦点定位到需要修正的字段 |
| 深浅色 / 高对比度 | 焦点、状态和文本仍可辨认；业务自定义色需重新测量对比度 |
| 200% / 400% 放大 | 320 CSS px 宽度可重排，操作可见，无不必要的页面横向滚动 |
| 触屏 | 点按可开关浮层，关键操作目标足够大，不依赖 hover |
| 减少动态效果 | 关闭动画后所有流程仍可使用 |

自动检查使用 axe 与真实浏览器行为断言，不进行截图基线对比。Chromium/WebKit 模拟的触摸与视口重排不能代替真机浏览器缩放测试。读屏器需另行人工验收：Windows + NVDA，macOS/iOS + VoiceOver，并记录版本、读出的名称/角色/状态及错误通知。未经人工执行的项目必须标记“待验收”。实际记录见仓库 `packages/react/ACCESSIBILITY.md`。
