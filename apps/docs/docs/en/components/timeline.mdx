# Timeline

Present events and progress in sequence.

{/* leaf:section basic */}

## Basic usage

Use `children` for the event content and `label` for supporting information such as a timestamp. Events follow the order of `items`, not an automatic sort by label. Use `reverse` to reverse the event order.

## Examples

### Alternating layout

`mode="alternate"` places events on alternating sides, including in narrow containers. Prefer the default one-sided layout for longer content. Use `mode="right"` to align all events to the right.

### Pending event

`pending` appends a waiting entry; it does not start requests or complete work automatically. This example adds a completed event in application state and removes the waiting entry by setting `pending` to `null`. With `reverse`, the waiting entry still stays at the end.

## API

### TimelineProps API

Configure timeline items, alignment and pending content.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `items` | `readonly `[`TimelineItem`](#timelineitem-api)`[]` | Required | Items; keep keys unique and stable |
| `mode` | `'left' \| 'right' \| 'alternate'` | `'left'` | Timeline layout: left, right or alternating. |
| `pending` | `ReactNode` | — | Pending content appended at the end; null or undefined omits it, while false and empty strings still retain a node. |
| `reverse` | `boolean` | `false` | Reverse items; pending is still appended at the end. |

### TimelineItem API

Describe the content, marker and color of an individual event.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `key` | `string` | Required | Unique stable identifier |
| `children` | `ReactNode` | Required | Main event content. |
| `label` | `ReactNode` | — | Secondary label, typically a timestamp. |
| `color` | `'primary' \| FeedbackType \| 'error' \| (string & {})` | — | Color; `error` is a compatibility alias |
| `dot` | `ReactNode` | — | Decorative custom dot; explain important status in the event text. |
