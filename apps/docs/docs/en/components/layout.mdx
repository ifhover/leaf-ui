### Responsive sidebar

`breakpoint` follows the viewport width, not the width of the example container. Below the threshold, the sidebar stays collapsed and hides its manual toggle without changing the controlled value or calling `onCollapse`.

This example uses the default `sm` breakpoint to keep the menu in sync. If you customize that theme breakpoint, update the sidebar threshold as well.

## API

### LayoutProps API

The arrangement direction of child elements in a layout container.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `direction` | `'horizontal' \| 'vertical'` | `'vertical'` | Layout direction of the children. |

### LayoutSiderProps API

When the viewport becomes wider again, the sidebar returns to the manual or controlled collapsed state. `trigger` replaces the content of the built-in toggle; the component still handles its click and accessible name.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `collapsed` | `boolean` | — | Controlled manual collapse state; the breakpoint may still force a collapsed presentation. |
| `defaultCollapsed` | `boolean` | `false` | Initial manual collapse state in uncontrolled mode. |
| `onCollapse` | `(collapsed: boolean) => void` | — | Called with the next state on manual toggling; breakpoint changes do not call it. |
| `width` | `number \| string` | `220` | Width, numbers are in pixels |
| `collapsedWidth` | `number \| string` | `64` | Collapsed width |
| `collapsible` | `boolean` | `false` | Show collapse controls |
| `trigger` | `ReactNode` | — | Custom trigger content |
| `breakpoint` | `number` | — | Collapse and hide the built-in trigger when viewport width is at or below this pixel value, without changing manual state. |
