# DataTable

Browse and work with structured data.

Import from the `@ifhover/leaf-ui/table` subpath; styles load automatically. Install the optional peer dependency before use:

```bash
npm install @tanstack/react-table@^8.21.3
```

### Pinning and resizing

Pin columns with TanStack `columnPinning`; column `size`, `minSize`, and `maxSize` control widths. Drag a header edge, or focus it and use arrow keys to resize. `maxHeight` keeps body scrolling inside the table.

When the combined pinned-column width exceeds the available scroll viewport, pinned columns temporarily scroll horizontally with the other columns to prevent overlap. Pinning resumes when space permits, without changing `columnPinning` state.

The table always renders its content and pagination automatically. Use `toolbar` for additional controls; column pinning and resizing stay in TanStack state and `resizable`.

### Server sorting and pagination

The component does not request data. Control sorting and pagination, set `manualSorting`, `manualPagination`, and `rowCount`, then supply the current page. Reset the page when sorting changes and clean up stale requests. TanStack callbacks accept either a value or updater function, both supported by React setters.

A timer mocks sorting before pagination and request failures; no server is contacted. For a real API, map sorting to request parameters and pass the `AbortSignal`. Omit `manualSorting` when controlling sorting state but retaining local sorting.

## API

### DataTable API

<a id="datatableinstance-api"></a>
<a id="datatabledata-api"></a>

Column definitions and state use native TanStack APIs; see [column definitions](https://tanstack.com/table/v8/docs/guide/column-defs) and [controlled state](https://tanstack.com/table/v8/docs/framework/react/guide/table-state). The table renders its layout automatically; the application owns search, column visibility and column order through TanStack state and custom controls.

Use `DataTableProps<TData>` for component props. Usually, pass `data`, `columns` and `rowKey` directly. To access the table instance in your application, create one with `useDataTable` or native `useReactTable` and pass it as `table` instead. Do not mix the two inputs.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `data` | `readonly TData[]` | Required without table | Data to display; provide a new array when updating. |
| `columns` | `readonly ColumnDef<TData>[]` | Required without table | Native TanStack column definitions. |
| `rowKey` | [`DataTableRowKey`](#datatablerowkey)`<TData>` | Required without table | A required string/number identity field, or a function returning a string/number identity. |
| `options` | `Omit<TableOptions<TData>, 'data' \| 'columns' \| 'getCoreRowModel' \| 'getRowId'>` | — | Customize TanStack state, callbacks and server configuration. |
| `localPagination` | `boolean` | — | Whether TanStack slices rows into local pages. Disable it to keep pagination state and controls while rendering all supplied rows. |
| `table` | `TanStackTable<TData>` | — | Instance from useDataTable or useReactTable; mutually exclusive with data, columns, rowKey, options and localPagination. |
| `toolbar` | `ReactNode` | — | Toolbar content in the automatic layout. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Presentation size. |
| `variant` | `'layered' \| 'simple'` | `'layered'` | layered uses a layered card; simple uses a square content-surface header without a frame, shadows or column dividers. |
| `columnDividers` | `boolean` | — | Add body and footer column dividers; layered headers keep short separators. Ignored in simple mode. |
| `striped` | `boolean` | `true` | Both variants default to alternating backgrounds from the second row and hide row dividers. Disable to show fine row dividers. |
| `maxHeight` | `CSSProperties['maxHeight']` | — | Maximum table viewport height. Headers always stay fixed while the body scrolls internally; virtual mode defaults to 400 when omitted. |
| `minWidth` | `CSSProperties['minWidth']` | — | Minimum table width; defaults to visible column sizes. |
| `loading` | `boolean` | `false` | Show a loading state. |
| `emptyContent` | `ReactNode` | — | Empty content. |
| `error` | `ReactNode` | — | Error content; null, undefined and false do not show an error. |
| `onRetry` | `() => void` | — | Retry action. |
| `selection` | `false \| 'single' \| 'multiple'` | `false` | None, single or multiple row selection. |
| `resizable` | `boolean` | `false` | Show resize handles for eligible columns. |
| `virtual` | `boolean \| `[`DataTableVirtualOptions`](#datatablevirtualoptions) | `false` | Explicit row virtualization. |
| `pagination` | `boolean \| `[`DataTablePaginationProps`](#datatablepagination-api) | `true` | Pagination visibility or display options; see <a href="pagination.html#pagination-api" target="_blank" rel="noopener noreferrer">Pagination API</a>. With direct data input, false also disables local slicing. |
| `tableRef` | `Ref<HTMLTableElement>` | — | Native table DOM ref. |
| `getRowLabel` | `(row: Row<TData>) => string` | — | Accessible row-action name; defaults to row.id. |
| `renderExpandedRow` | `(row: Row<TData>) => ReactNode` | — | Leaf-row details; configure getRowCanExpand. |
| `getRowProps` | `(row: Row<TData>) => `[`DataTableRowProps`](#datatablerow-api) | — | Custom row attributes/events. |
| `getCellProps` | `(cell: Cell<TData, unknown>) => `[`DataTableCellProps`](#datatablecell-api) | — | Cell attributes, styles or spans; a zero colSpan / rowSpan omits the cell. |

aria-label/aria-labelledby name the native table; other div attributes apply to the wrapper.

<a id="datatablerowkey"></a>

`DataTableRowKey<TData>` accepts required string/number fields or a `(row: TData, index: number) => string | number` function. Boolean, object, array and optional fields cannot be used directly. When records have no natural identity, generate stable unique business keys rather than using indices after sorting or pagination.

<a id="datatablerow-api"></a>

`DataTableRowProps`, returned by `getRowProps`, supports native `tr` attributes and events, plus `selected?: boolean` to apply the selected row appearance.

<a id="datatablecell-api"></a>

`DataTableCellProps`, returned by `getCellProps`, supports native `td` attributes, events and `colSpan` / `rowSpan`. Its additional `align` accepts `'start' | 'center' | 'end'` and defaults to `'start'`. A zero span omits the cell.

<a id="datatablepresentation-api"></a>

[ConfigProvider](config-provider#configprovider-api) accepts row-independent presentation props from the main table, such as `size`, `variant` and `pagination`, through `components.DataTable`; `tableRef` is not supported. Import `DataTablePresentationProps` from `@ifhover/leaf-ui` to type reusable defaults. Configuring defaults alone does not require TanStack Table; using DataTable still requires it.

### useDataTable

<a id="usedatatableoptions"></a>

`UseDataTableOptions<TData>` reuses `data`, `columns`, `rowKey`, `localPagination` and `options` from [DataTable API](#datatable-api). The first three are required; the others are optional. `localPagination` controls local slicing, while DataTable still configures the pagination UI.

`useDataTable<TData>(config: UseDataTableOptions<TData>): TanStackTable<TData>`

The Hook creates and returns one stable native instance. It does not read DataTable presentation defaults or fetch data. Filtering, pagination and expansion use local row models. A sorting model is configured, but sorting is disabled until you explicitly set `options.enableSorting: true`. Use `options` to override models and server settings; `manualSorting: true` hands data ordering to your application but does not enable sort buttons by itself. Pass the instance to DataTable or use native TanStack APIs in your application. Enable detail rows explicitly with `options.getRowCanExpand`.

### useDataTableSelection

`useDataTableSelection(options?): UseDataTableSelectionResult`

Manage TanStack row selection with business row keys, without maintaining another `RowSelectionState`:

```tsx
const selection = useDataTableSelection({
  mode: 'multiple',
  selectedRowKeys: selectedKeys,
  onSelectedRowKeysChange: setSelectedKeys,
});

const table = useDataTable({
  data,
  columns,
  rowKey: 'id',
  options: selection.selectionOptions,
});
```

Pass `selection.selectionOptions` directly as DataTable or `useDataTable` options, or spread it into native `useReactTable` configuration. Business keys accept strings or numbers and are returned as unique strings. Single mode keeps the most recently requested key; multiple mode keeps all selected keys. `clearSelection()` requests an empty selection and notifies the callback; controlled usage must update `selectedRowKeys`. Row IDs must match `rowKey` / `getRowId`.

#### Parameters (UseDataTableSelectionOptions)

<a id="usedatatableselectionoptions"></a>

Configure controlled or uncontrolled selection using business row keys.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `mode` | `'single' \| 'multiple'` | `multiple` | Single keeps only the most recently requested key; multiple keeps every selected key. |
| `selectedRowKeys` | `readonly DataTableRowSelectionKey[]` | — | Controlled selected business row keys; array order determines which key single mode retains. |
| `defaultSelectedRowKeys` | `readonly DataTableRowSelectionKey[]` | `[]` | Initial selected business row keys for uncontrolled usage. |
| `onSelectedRowKeysChange` | `(selectedRowKeys: string[]) => void` | — | Called with normalized, unique string keys whenever selection changes. |

#### Return value (UseDataTableSelectionResult)

<a id="usedatatableselectionresult"></a>

Return business row keys, native selection state and a clear action.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `selectedRowKeys` | `string[]` | Required | Current selected business row keys; sourced from selectedRowKeys when controlled, otherwise from internal state. |
| `rowSelection` | `RowSelectionState` | Required | Native TanStack rowSelection map derived from business keys. |
| `onRowSelectionChange` | `OnChangeFn<RowSelectionState>` | Required | Pass directly to useDataTable or native useReactTable. |
| `selectionOptions` | [`DataTableSelectionOptions`](#datatableselectionoptions) | Required | Complete selection options ready to spread into useDataTable options. |
| `clearSelection` | `() => void` | Required | Clear controlled or uncontrolled selection and notify the change callback. |

#### TanStack integration (DataTableSelectionOptions)

<a id="datatableselectionoptions"></a>

Use `DataTableSelectionOptions` when merging TanStack configuration manually. Preserve other application state when merging `state`.

<details className="leaf-api-details">
<summary>View native selection configuration</summary>

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `state` | `{ rowSelection: RowSelectionState }` | Required | Controlled rowSelection state for useDataTable options. |
| `onRowSelectionChange` | `OnChangeFn<RowSelectionState>` | Required | Native TanStack selection callback; business keys are normalized internally. |
| `enableMultiRowSelection` | `boolean` | Required | Derived from mode: false for single and true for multiple. |

### DataTableColumnMeta

<a id="datatablecolumndef"></a>

Use these properties on TanStack column `meta`, and supply `label` for functional headers. `DataTableColumnDef<TData, TValue>` adds `DataTableColumnMeta` constraints to native `ColumnDef` metadata for completion and spelling checks, without augmenting TanStack's global types. Native column definitions remain supported.

```tsx
import type { DataTableColumnDef } from '@ifhover/leaf-ui/table';

type Member = { id: string; name: string };

const columns = [
  { accessorKey: 'name', header: 'Name', meta: { align: 'start', label: 'Name' } },
] satisfies DataTableColumnDef<Member>[];
```

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | — | Plain-text column name for sorting and resize controls. |
| `align` | `'start' \| 'center' \| 'end'` | `'start'` | Header and cell alignment. |
| `cellClassName` | `string` | — | Cell class. |
| `headerClassName` | `string` | — | Header class. |

### DataTableVirtualOptions

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `estimateRowHeight` | `number` | `48` | Estimated height before measuring. |
| `overscan` | `number` | `5` | Additional rows before/after the viewport. |

### DataTablePagination API

See <a href="pagination.html#pagination-api" target="_blank" rel="noopener noreferrer">Pagination API</a> (opens in a new tab) for shared display options. Only DataTable differences are listed here.

- `total`, `current`, `pageSize` and `onChange` belong to the table instance. `defaultCurrent` and `defaultPageSize` are not accepted; set initial pagination through the instance's `initialState.pagination`.
- `showSizeChanger` defaults to true, and `size` inherits from DataTable.
- Unknown totals (`pageCount: -1`) show Previous/Next only. The additional `hasNextPage?: boolean` controls next-page availability; when omitted, the instance decides.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `hasNextPage` | `boolean` | — | Control next-page availability when the total is unknown. |
