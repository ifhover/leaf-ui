# DataTable

Browse, filter and manage structured data.

## Installation

DataTable accepts data and columns for sorting and pagination, or your own TanStack Table instance for filtering, selection, expansion and column controls. Install the peer dependency before using it:

```bash
npm install @tanstack/react-table@^8.21.3
```

```tsx
import { DataTable } from '@ifhover/leaf-ui/table';
import type { DataTableProps, DataTableColumnMeta } from '@ifhover/leaf-ui/table';
```

The table subpath loads its styles automatically. Import DataTable and its data types from `@ifhover/leaf-ui/table`; DataTable is not exported from the library root.

The `data + columns + rowKey` mode creates one TanStack instance and uses the same renderer as the advanced mode. `rowKey` must identify a required string/number field or return a string/number; identities must be stable and unique. Local sorting, filtering, pagination and expansion are configured by default. Use `options` for initial state, controlled callbacks or server configuration. `localPagination={false}` keeps pagination state and controls but stops slicing rows locally; `pagination={false}` remains a legacy shorthand that also hides the footer. Toggling does not remount the instance or clear selection.

These modes are mutually exclusive: when supplying `table`, do not also pass `data`, `columns`, `rowKey` or `options`. Use `useDataTable` when you need access to the instance, or native `useReactTable` for complete row-model configuration.

Put only the state and callbacks required by your application into `options`; TanStack manages the rest. This example uses `useDataTableSelection` to map business row keys to TanStack `rowSelection` without also controlling sorting, filtering or pagination. Pass `selectedRowKeys` and `onSelectedRowKeysChange` for controlled selection; omit both for internal state. Controlled callbacks use the native TanStack value-or-updater contract.

`toolbar` inserts content above the default table. `pagination={{ ... }}` customizes presentation options such as `pageSizeOptions`, `showTotal` and `hasNextPage`. Pagination state still belongs in `options.state.pagination` / `options.initialState.pagination`, not a second state store.

## Frame, column dividers and striped rows

DataTable always shows a base-radius outer frame and a downward resting shadow by default. The frame uses the same softened divider color as Card; the header keeps the same surface as the table with a 1px divider below it. `striped` remains enabled by default, while `columnDividers` adds column dividers only. The legacy `bordered` alias still works but is deprecated. Headers are bold and slightly lighter than body text, with sorting icons immediately after the label. Stripes start on the first body row with a faint background and hide row dividers; set `striped={false}` to show fine dividers between rows. Ordinary and striped rows use the same opaque primary-tinted hover background; selected rows use a light primary background that takes precedence over hover.

## Sorting, filtering, selection and pagination

`useDataTable` returns a regular TanStack instance with the same row models, stable keys and RTL resize direction as data mode. Read selection, reset filters or build bulk actions without manually configuring every row model and controlled state:

<ComponentExample title="Manage team members" preview={<TableData english />} fileName="data.tsx" width="100%">

```tsx lineNumbers file="../../../src/examples/table/data.tsx"
```

</ComponentExample>

The provided instance is the **only state owner**. Leaf UI does not sort or paginate the data again, or create a second filter/expansion store; `useDataTableSelection` only maps business keys to `rowSelection`. `useDataTable` configures the common local row models; with native `useReactTable`, configure the row models your application needs:

| Feature | TanStack configuration |
| --- | --- |
| Data | `getCoreRowModel()` |
| Client sorting | `getSortedRowModel()` |
| Client filtering | `getFilteredRowModel()` |
| Client pagination | `getPaginationRowModel()` |
| Tree/group expansion | `getExpandedRowModel()` and `getSubRows` for trees |
| Detail rows | `getRowCanExpand` and DataTable `renderExpandedRow` |
| Grouping and totals | `getGroupedRowModel()`, `aggregationFn`, `aggregatedCell` |

Provide a stable `getRowId`; do not use an index after sorting or pagination. Select-all defaults to selectable rows on the current page. `selectAllMode="all"` selects loaded, filtered records, **not unloaded server records**. Selection keys persist across pages in TanStack state; for server data use these keys rather than assuming `getSelectedRowModel()` contains unloaded records.

DataTable.Search updates the global filter unless columnId is specified. ColumnVisibility respects `enableHiding: false`. Shift-click a header for multi-sort; aria-sort identifies the primary sort column.

## Sticky headers, pinned columns and resizing

<ComponentExample title="Pinned columns and column sizing" preview={<TableColumns english />} fileName="data.tsx" width="100%">

```tsx lineNumbers file="../../../src/examples/table/data.tsx"
```

</ComponentExample>

Control pinning through `columnPinning`, order through `columnOrder`, and widths through each column's `size`, `minSize` and `maxSize`. Leaf interprets left/right as logical start/end sides. For RTL also configure TanStack `columnResizeDirection: 'rtl'`. A pinned-column shadow appears only while hidden content remains in that direction and disappears at the corresponding logical scroll edge. Styles returned by `getCellProps` cannot override internal pinned positioning.

Tables fill their container and scroll horizontally only when the columns need more space. Headers are sticky by default. Set `maxHeight` to scroll overflowing rows within the body. Overlay tracks use [Scrollbar](./scrollbar); the vertical track starts below the header. When content fits or reaches an edge, wheel scrolling continues to the page.

Drag a resize handle or focus it and press Left/Right. Shift increases the step; Home/End moves to its bounds; double-click resets its width. Set a sensible maxSize. ConfigProvider density and theme.components.Table customize spacing, radius, typography, foreground, background and shadow.

## Row and column reordering

<ComponentExample title="Arrange team priorities" preview={<TableReordering english />} fileName="reordering.tsx" width="100%">

```tsx lineNumbers file="../../../src/examples/table/reordering.tsx"
```

</ComponentExample>

Handles support pointer, touch and keyboard interaction. Focus a handle, press Space to start, use arrow keys to move, Space to drop or Escape to cancel. `onRowReorder` returns the reordered current-page rows and stable identifiers; the application updates its data or submits the server change. Column dragging writes directly to TanStack's `columnOrder`.

Row handles are only shown for flat, nonvirtual tables without active sorting, filtering, grouping or expansion, so display order cannot conflict with business order. Column handles support single-level headers and stay within the same pinned region. For grouped headers, set `columnOrder` explicitly. Reordering preserves row selection and mounted editor state.

Row virtualization is explicit and off by default. Set maxHeight and an appropriate estimated height; dynamic heights are measured and a focused row is retained when scrolling. SSR renders an estimated window before client measurement.

This is not a spreadsheet DataGrid: it does not add arrow-key cell navigation, column virtualization or automatic mobile cards. Tables retain native semantics and horizontal scrolling. For screen-reader users who need all data in the accessibility tree, disable virtualization and use pagination.

## Server data

<ComponentExample title="Remote pagination and retry" preview={<TableServer english />} fileName="advanced.tsx" width="100%">

```tsx lineNumbers file="../../../src/examples/table/advanced.tsx"
```

</ComponentExample>

Use `manualPagination` with `rowCount`, and `manualSorting` / `manualFiltering` for corresponding server features. Use controlled TanStack state as request parameters and cancel stale requests. Set `pageCount: -1` for unknown totals; the footer then offers only Previous/Next. Supply `<DataTable.Pagination hasNextPage={hasMore} />` to prevent advancing past the available records.

Refreshing keeps existing rows, adds a loading overlay and prevents duplicate interactions. First load, empty data and errors have separate state rows. The automatic layout renders content and includes pagination when that capability exists; `toolbar` only adds the toolbar. For a custom composition, set `layout="custom"` and arrange Toolbar, Content and Footer explicitly. For compatibility, omitting `layout` still lets children replace the automatic layout, but emits a development warning; `layout="auto"` ignores children and renders the automatic layout.

In data mode, `pagination={false}` hides the default footer and disables local slicing. With a supplied `table`, it only hides the default footer and never changes the external instance. With `useDataTable`, control local slicing with `localPagination` and footer visibility with DataTable's `pagination`. `localPagination={false}` forces local slicing off; when it is `true`, `options.manualPagination` remains authoritative. Server pagination uses `options.manualPagination: true`. The Hook's `pagination` prop remains only as a compatibility alias.

When the table lacks the corresponding `getFilteredRowModel()` / `manualFiltering`, `getPaginationRowModel()` / `manualPagination` or similar capability, related interactions are hidden or disabled with a development warning. `DataTable.Search` is also disabled for a missing or unfilterable `columnId`.

`DataTable.Search` enables its clear action and inherits the DataTable size by default; `DataTable.Pagination` enables its page-size selector by default. Pass `false` to opt out.

Unknown-total pagination preserves native `id`, `style`, events, `dir` and accessible names. It only offers Previous/Next; `showSizeChanger`, `showQuickJumper`, `showTotal`, `simple` and `hideOnSinglePage` do not apply in this mode.

## DataTable API

These props are shared by both modes. `DataTableProps<TData>` is `DataTableInstanceProps<TData> | DataTableDataProps<TData>`. Use this union when forwarding the complete component props, or `DataTableInstanceProps<TData>` for an instance-only wrapper. Mode-specific props are listed under [instance mode](#datatableinstance-api) and [data mode](#datatabledata-api).

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `layout` | `'auto' \| 'custom'` | — | Explicitly choose the built-in layout or a fully custom composition. When omitted, legacy behavior applies: children replace the automatic layout; only children={false} keeps the automatic layout. |
| `children` | `ReactNode` | — | The complete composition for layout="custom". With layout omitted, children replace the automatic layout and emit a development warning. Do not place nested row data here. |
| `toolbar` | `ReactNode` | — | Toolbar content in the automatic layout; DataTable still renders Content and pagination. Compose public parts directly for a custom layout. |
| `caption` | `ReactNode` | — | Table caption. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Presentation size. |
| `columnDividers` | `boolean` | — | Add column dividers only; the outer frame, radius and downward resting shadow are always enabled. |
| `bordered` | `boolean` | `false` | Deprecated; use columnDividers instead. An explicit columnDividers value takes precedence. |
| `striped` | `boolean` | `true` | Alternate row backgrounds and hide row dividers. Disable to show fine dividers between rows. |
| `stickyHeader` | `boolean` | `true` | Keep headers at the top of the scroll region. |
| `maxHeight` | `CSSProperties['maxHeight']` | — | Maximum scroll height; virtual mode defaults to 400 when omitted. |
| `minWidth` | `CSSProperties['minWidth']` | — | Minimum table width; defaults to visible column sizes. |
| `loading` | `boolean` | `false` | Show a loading state. |
| `emptyContent` | `ReactNode` | — | Empty content. |
| `error` | `ReactNode` | — | Error content; null, undefined and false do not show an error. |
| `onRetry` | `() => void` | — | Retry action. |
| `selection` | `false \| 'single' \| 'multiple'` | `false` | None, single or multiple row selection. |
| `selectAllMode` | `'page' \| 'all'` | `'page'` | Select the page or all loaded selectable rows. |
| `resizable` | `boolean` | `false` | Show resize handles for eligible columns. |
| `columnReordering` | `boolean` | `false` | Show drag handles for single-level headers. |
| `virtual` | `boolean \| `[`DataTableVirtualOptions`](#datatablevirtualoptions) | `false` | Explicit row virtualization. |
| `pagination` | `boolean \| `[`DataTablePaginationProps`](#datatablepagination-api) | `true` | Automatic pagination visibility or presentation options; false also disables local slicing in data mode. |

| `onRowReorder` | `(info: `[`DataTableRowReorderInfo`](#datatablerowreorderinfo)`<TData>) => void` | — | Show row handles and return reordered current-page rows; the application updates the data. |
| `localPagination` | `boolean` | — | Whether TanStack slices rows into local pages. Disable it to keep pagination state and controls while rendering all supplied rows. |

## DataTableColumnMeta

Use these optional properties on TanStack column meta, and supply `label` for functional headers. The optional `DataTableColumnDef<TData, TValue>` alias adds completion and spelling checks to native `ColumnDef` metadata without augmenting TanStack's global types. Native column definitions remain supported.

```tsx
import type { DataTableColumnDef, DataTableColumnMeta } from '@ifhover/leaf-ui/table';
import type { ColumnDef } from '@tanstack/react-table';

type Member = { id: string; name: string };

const columns = [
  { accessorKey: 'name', header: 'Name', meta: { align: 'start', label: 'Name' } },
] satisfies DataTableColumnDef<Member>[];

const nativeColumn: ColumnDef<Member> = {
  accessorKey: 'name',
  meta: { align: 'start' } satisfies DataTableColumnMeta,
};
```

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | — | Plain-text column name used by controls. |
| `align` | `'start' \| 'center' \| 'end'` | `'start'` | Header and cell alignment. |
| `cellClassName` | `string` | — | Cell class. |
| `headerClassName` | `string` | — | Header class. |

## useDataTable

`useDataTable<TData>(config: UseDataTableOptions<TData>): TanStackTable<TData>`

The Hook creates and returns one stable native instance. It does not read DataTable presentation defaults or fetch data. Local sorting, filtering, pagination and expansion models are configured; `options` can override the corresponding models and server settings. Pass the instance to DataTable or use native TanStack APIs in your application. Enable detail rows explicitly with `options.getRowCanExpand`.

## useDataTableSelection

`useDataTableSelection(options?): UseDataTableSelectionResult`

Manage TanStack row selection with business row keys, without maintaining another `RowSelectionState`:

```tsx
const selection = useDataTableSelection({
  mode: 'multiple',
  selectedRowKeys: selectedKeys,
  onSelectedRowKeysChange: setSelectedKeys,
});

const table = useDataTable({
  data,
  columns,
  rowKey: 'id',
  options: selection.selectionOptions,
});
```

Spread `selection.selectionOptions` into `useDataTable` options or pass it to native `useReactTable`. `selectedRowKeys` is uncontrolled or controlled and returns the latest single key or all multiple keys; `clearSelection()` clears state and notifies the callback. Row IDs must match `rowKey` / `getRowId`.

| --- | --- | --- | --- |
| `state` | `{ rowSelection: RowSelectionState }` | — | Required. Controlled rowSelection state for useDataTable options. |
| `onRowSelectionChange` | `OnChangeFn<RowSelectionState>` | — | Required. Native TanStack selection callback; business keys are normalized internally. |
| `enableMultiRowSelection` | `boolean` | — | Required. Derived from mode: false for single and true for multiple. |

## UseDataTableSelectionOptions

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `mode` | `'single' \| 'multiple'` | `multiple` | Single keeps only the most recently requested key; multiple keeps every selected key. |
| `selectedRowKeys` | `readonly DataTableRowSelectionKey[]` | — | Controlled selected business row keys; array order determines which key single mode retains. |
| `defaultSelectedRowKeys` | `readonly DataTableRowSelectionKey[]` | `[]` | Initial selected business row keys for uncontrolled usage. |
| `onSelectedRowKeysChange` | `(selectedRowKeys: string[]) => void` | — | Called with normalized, unique string keys whenever selection changes. |

## UseDataTableSelectionResult

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `selectedRowKeys` | `string[]` | — | Required. Current selected business row keys; sourced from selectedRowKeys when controlled, otherwise from internal state. |
| `rowSelection` | `RowSelectionState` | — | Required. Native TanStack rowSelection map derived from business keys. |
| `onRowSelectionChange` | `OnChangeFn<RowSelectionState>` | — | Required. Pass directly to useDataTable or native useReactTable. |
| `selectionOptions` | [`DataTableSelectionOptions`](#datatableselectionoptions) | — | Required. Complete selection options ready to spread into useDataTable options. |
| `clearSelection` | `() => void` | — | Required. Clear controlled or uncontrolled selection and notify the change callback. |
