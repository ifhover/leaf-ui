## Settings layout

Set `layout="settings"` to place labels and `description` on the left and naturally sized controls on the right, with dividers between fields. For wider controls, set `FormField layout="vertical"` to place the label and description above a full-width control. Fields stack automatically on narrow screens.

Use `description` to explain a field beside its label. Use `help` for guidance below the control; validation feedback from `error` replaces `help`.

## Form API

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `layout` | `'horizontal' \| 'vertical' \| 'settings'` | `'horizontal'` | Default field layout; settings places labels and descriptions on the left and controls on the right |
| `labelWidth` | `number \| 'auto'` | `'auto'` | Horizontal fields only: a pixel width, or auto to align labels to the widest label |
| `labelAlign` | `'left' \| 'right'` | `'right'` | Label alignment for horizontal fields |
| `disabled` | `boolean` | `false` | Disable interaction. |
| `ref` | `Ref<HTMLFormElement>` | — | Reference to the form |

## FormField API

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `ReactNode` | — | Field label |
| `description` | `ReactNode` | — | Description below the label, displayed independently of help and error below the control |
| `layout` | [`FormProps`](#form-api)`['layout']` | Inherited from Form | Override this field's layout; vertical allows wider controls to fill the row |
| `htmlFor` | `string` | Generated | The associated control ID; one field wraps one control or group |
| `required` | `boolean` | `false` | Require a non-empty value; compound controls validate once. |
| `help` | `ReactNode` | — | Supporting text below the control, included in the field layout |
| `error` | `ReactNode` | — | Error message, displayed instead of help |
| `labelWidth` | `number` | — | Override this horizontal field’s label width in pixels |

## Usage notes

The default horizontal layout aligns labels to the widest horizontal field label in the Form. Widths update when text, fonts or mounted fields change. Vertical layouts and narrow screens stack labels above fields. A FormField can override the Form layout with its own layout prop; labelWidth and labelAlign only apply to horizontal fields. Standard form attributes such as action, method, onSubmit and onReset are supported.

Help and error messages occupy normal layout space and preserve the form gap before the next field. Wrapped text naturally adds height.

Read named controls with FormData. Use required, type and minLength for basic validation; errors appear beside their fields. Pass application or server errors through error. Set noValidate when handling validation yourself. FormData contains strings, does not build nested objects, and omits unchecked checkboxes. Reset controlled fields in application state.

## React Hook Form integration

Install react-hook-form in your application. Use register with native inputs and Controller with components whose onChange returns a value. Leaf Form handles layout; the form library owns validation and state. Use noValidate to take over validation. FormList names are plain field names; use useFieldArray when React Hook Form manages the collection.

```tsx
import { useForm, Controller } from 'react-hook-form';
import { Form, FormField, FormErrorSummary, Input, Select, Button } from '@ifhover/leaf-ui';

export function AccountForm() {
  const { register, control, handleSubmit, formState: { errors } } = useForm({ defaultValues: { email: '', role: '' } });
  return <Form noValidate onSubmit={handleSubmit(values => console.log(values))}>
    <FormErrorSummary />
    <FormField label="Email" error={errors.email?.message}>
      <Input {...register('email', { required: 'Enter an email' })} />
    </FormField>
    <Controller name="role" control={control} rules={{ required: 'Choose a role' }} render={({ field, fieldState }) =>
      <FormField label="Role" error={fieldState.error?.message}>
        <Select {...field} options={[{ value: 'editor', label: 'Editor' }]} />
      </FormField>}
    />
    <Button type="submit">Save</Button>
  </Form>;
}
```

## FormValidationApi

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `errors` | `Record<string, string>` | Required | Field-keyed errors for FormField. |
| `pending` | `boolean` | Required | Whether validation or submission is pending. |
| `setErrors` | `Dispatch<SetStateAction<Record<string, string>>>` | Required | Set server or business errors. |
| `handleSubmit` | `(event: FormEvent<HTMLFormElement>) => Promise<void>` | Required | Bind to Form.onSubmit. |
| `handleReset` | `(event: FormEvent<HTMLFormElement>) => void` | Required | Bind to Form.onReset to cancel requests and clear errors. |
| `cancel` | `() => void` | Required | Cancel the current request. |
| `clearErrors` | `(name?: string) => void` | Required | Clear one or all errors and cancel stale requests. |

| --- | --- | --- | --- |
