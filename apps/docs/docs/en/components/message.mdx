# Message

Provide brief feedback about an operation.

## Set up once

Wrap your application in `ConfigProvider`. It manages messages automatically, so pages and business components can call `useMessage` directly.

```tsx
import { ConfigProvider } from '@sudden3/leaf-ui';
import '@sudden3/leaf-ui/styles.css';

export function Root() {
  return <ConfigProvider><App /></ConfigProvider>;
}
```

Applications already using `ConfigProvider` need no additional setup. Call `useMessage` in its descendants; the returned `message` can also be passed to business functions.

## useMessage API

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `message` | [`MessageApi`](#messageapi) | — | Call the queue managed by the application provider |

## MessageProvider API

If your application has no `ConfigProvider`, add `MessageProvider` at the entry point. An explicit `MessageProvider` also creates an independent queue for a region.

```tsx
import { MessageProvider } from '@sudden3/leaf-ui';

export function Root() {
  return <MessageProvider><App /></MessageProvider>;
}
```

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `ReactNode` | — | Components sharing this queue |

## MessageApi

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `open` | [`(options: MessageOptions) => string`](#messageoptions) | — | Create or update by key; returns the key |
| `success / info / warning / error` | `(content: ReactNode, duration?: number) => string` | — | Show feedback of the specified type |
| `loading` | `(content: ReactNode) => string` | — | Persistent loading message; returns the key |
| `close` | `(key?: string) => void` | — | Close one message, or all when key is omitted |

## MessageOptions

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `key` | `string` | Generated | Use the same key to update a message |
| `content` | `ReactNode` | Required | Message content |
| `type` | `'success' \| 'info' \| 'warning' \| 'error' \| 'loading'` | `'info'` | Message type |
| `duration` | `number` | `3` | Seconds before dismissal; 0 persists, loading defaults to 0 |
| `closable` | `boolean` | `false` | Show a close button |
| `onClose` | `() => void` | — | Called once when dismissal starts |

## Message API

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `open` | `boolean` | Required | Controlled visibility |
| `content` | `ReactNode` | Required | Message content |
| `type` | `'success' \| 'info' \| 'warning' \| 'error' \| 'loading'` | `'info'` | Message type |
| `duration` | `number` | `3` | Duration in seconds; 0 persists, loading defaults to 0 |
| `closable` | `boolean` | `false` | Close button |
| `onClose / afterClose` | `() => void` | — | Requests closure / closing animation completed |

## Types

Import types when defining reusable component props or assembling options.

```ts
import type { MessageProps, MessageOptions, MessageApi, MessageProviderProps } from '@sudden3/leaf-ui';
```

## Usage notes

Prefer `useMessage`. Update a loading message with its `key` to show the result. Timers pause while a message is hovered or focused and resume with the remaining time.

Components under the same entry provider share a queue. `close()` closes all its messages; `close(key)` closes one. Nested `ConfigProvider` regions share that queue, while each message keeps the theme and language of the calling component.

Messages continue after the calling component unmounts, and asynchronous work can update them through the same `message` instance. Unmounting the entry provider clears its messages and timers. Separate React applications and SSR requests have independent queues.

`Message` also supports declarative rendering; set `open=false` after `onClose`.
