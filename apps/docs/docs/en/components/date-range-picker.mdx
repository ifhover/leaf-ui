# DateRangePicker

Choose a date, datetime or time range. Calendar modes use local `Date` tuples; time-only mode uses string tuples. Use [DatePicker](/en/components/date-picker) for a single value.

{/* leaf:section basic */}

## Basic usage

Select the start, then the end to commit a complete range and close the panel. Date mode supports reversed selection and orders the result from start to end. Set an initial uncontrolled range with `defaultValue`.

## Examples

### Controlled value and selection progress

`onChange` receives the committed range and two formatted strings; clearing returns `null` and `['', '']`. `onCalendarChange` observes panel-selection drafts and the edited endpoint, not a committed range, and does not cover every text or preset change. Update application state when resetting a controlled field.

### Date-time ranges

With `picker="datetime"`, choose the start date and time, select Next to edit the end, then OK to commit. The datetime panel requires the end not to precede the start. `defaultTime` supplies times for newly picked endpoints, not an initial range.

<ComponentExample exampleId="datetime" preview={<DateRangePickerDateTime />} fileName="datetime.tsx">

```tsx lineNumbers file="../../../src/examples/en/date-range-picker/datetime.tsx"
```

</ComponentExample>

This mode defaults to `needConfirm={true}` and discards an unconfirmed range on outside clicks. Other calendar modes commit after choosing an end by default; set `needConfirm` to require confirmation. Escape discards the current edit. Clearing or choosing a valid preset commits directly.

### Restrict selectable endpoints

`minDate` / `maxDate` include their boundaries. `disabledDate` receives `position` to distinguish start and end. This example restricts endpoints to October and excludes Sundays as endpoints; a range may still span a Sunday. Validate whole-range availability in the application if required.

<ComponentExample exampleId="disabled-dates" preview={<DisabledDates />} fileName="disabled-dates.tsx">

```tsx lineNumbers file="../../../src/examples/en/date-range-picker/disabled-dates.tsx"
```

</ComponentExample>

Restrictions apply to typing and panel selection without clearing existing values. Datetime bounds compare complete timestamps; `disabledTime` receives time parts, endpoint position and the current date. `inputReadOnly` prevents typing, while `readOnly` prevents changes.

### Open endpoints

`allowEmpty` permits empty endpoints independently. This example uses `[false, true]` for a required start and optional end, with `OpenDateRange` imported from the root entry. At least one endpoint must remain non-empty; use `null`, not `[null, null]`, to clear the whole control.

<ComponentExample exampleId="open-end" preview={<OpenEnd />} fileName="open-end.tsx">

```tsx lineNumbers file="../../../src/examples/en/date-range-picker/open-end.tsx"
```

</ComponentExample>

Clear an allowed endpoint with the panel footer action; its callback string is `''`. Opening with only a start continues editing the end.

### Time range

With `picker="time"`, values and callbacks use `['HH:mm', 'HH:mm']` or `null`, or `HH:mm:ss` with `showSeconds`. `use12Hours` changes display only; values stay in 24-hour format. `minTime` / `maxTime` apply to both endpoints. Time-only mode does not support `allowEmpty`.

### Display format and form submission

A custom `format` changes display and the string tuple passed to `onChange`. FormData retains canonical formats joined as `start/end`. This example displays `DD/MM/YYYY` and submits a value such as `2026-10-05/2026-10-09`; an open end produces `2026-10-05/`, and clearing produces an empty string. Resetting an uncontrolled field restores `defaultValue`.

<ComponentExample exampleId="form" preview={<DateRangePickerForm />} fileName="form.tsx">

```tsx lineNumbers file="../../../src/examples/en/date-range-picker/form.tsx"
```

</ComponentExample>

For canonical period/datetime formats and custom `parse`, see [DatePicker: display format and form submission](/en/components/date-picker#display-format-and-form-submission). Dates are local calendar values; handle business timezone conversion in the application. See [Form](/en/components/form) for other form configuration.

Paste a complete date range with endpoints separated by `~`. Enter commits valid input. Invalid or incomplete input reverts when focus leaves the whole control; Escape discards the edit. See [DatePicker: input and confirmation](/en/components/date-picker#input-and-confirmation) for segmented input.

## API

### DateRangePicker API

The main table covers calendar and time-only branches, but not every prop applies to both. `allowEmpty`, `format`, `parse`, `presets`, date bounds and calendar configuration belong to calendar modes; `allowOvernight` and `minTime` / `maxTime` belong to time-only mode.

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `picker` | `'year' \| 'quarter' \| 'month' \| 'week' \| 'date' \| 'datetime' \| 'time'` | `'date'` | Select a date, time, date-time, week, month, quarter or year. |
| `value` | `readonly [Date, Date] \| null \| readonly [Date \| null, Date \| null] \| readonly [string, string]` | — | Controlled range: a Date tuple for date modes, with nullable endpoints when allowEmpty is enabled; a 24-hour string tuple for time. The empty range is null. |
| `defaultValue` | `readonly [Date, Date] \| null \| readonly [Date \| null, Date \| null] \| readonly [string, string]` | `null` | Initial uncontrolled range matching picker, restored on native form reset. |
| `onChange` | `(((value: readonly [Date, Date] \| null, dateStrings: readonly [string, string]) => void)) \| (((value: readonly [Date \| null, Date \| null] \| null, dateStrings: readonly [string, string]) => void)) \| ((value: readonly [string, string] \| null) => void)` | — | Called when committing a range: Date and string tuples for date modes, a string tuple for time, null on clear. |
| `onCalendarChange` | `(range: readonly [Date \| null, Date \| null], info: { position: 'start' \| 'end' }) => void` | — | Called for date-panel draft, time and endpoint-clear changes, not a commit; text input and presets do not necessarily call it. |
| `allowEmpty` | `false \| true \| readonly [boolean, boolean]` | `false` | Explicitly allow open range endpoints. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Control size |
| `status` | `'error' \| 'warning'` | — | Validation appearance |
| `disabled` | `boolean` | `false` | Disable interaction. |
| `inputReadOnly` | `boolean` | — | Disable typing while retaining panel selection. |
| `allowClear` | `boolean` | `true` | Show the clear button |
| `minDate` | `Date` | — | Earliest / latest allowed values |
| `maxDate` | `Date` | — | Earliest / latest allowed values |
| `disabledDate` | `(date: Date, position: 'start' \| 'end') => boolean` | — | Restrict endpoints, not every date inside the range; position identifies start or end. |
| `minTime` | `string` | — | Earliest selectable time, inclusive, as HH:mm or HH:mm:ss. |
| `maxTime` | `string` | — | Latest selectable time, inclusive, as HH:mm or HH:mm:ss. |
| `disabledTime` | `((parts: `[`TimeParts`](date-picker#timeparts)`, position: 'start' \| 'end', date: Date) => boolean) \| ((parts: `[`TimeParts`](date-picker#timeparts)`, position: 'start' \| 'end') => boolean)` | — | Restrict endpoint times; datetime mode also receives the endpoint Date. |

| `defaultTime` | `readonly [string, string]` | `['00:00:00', '23:59:59']` | Times applied to newly picked start and end dates in datetime mode, as HH:mm[:ss]. |
| `format` | `string \| ((date: Date) => string)` | — | Display format; dates support YYYY, MM, DD, HH, mm, ss and Q. |
| `parse` | `(text: string) => Date \| null` | — | Parse entered text; return null on failure. |
| `presets` | `readonly `[`DatePreset`](date-picker#datepreset)`<readonly [Date \| null, Date \| null]>[]` | — | Presets; value may be computed on demand. |
| `panelValue` | `Date` | — | Controlled date displayed by the calendar panel. |
| `onPanelChange` | `(date: Date) => void` | — | Called when the displayed calendar period changes. |
| `cellRender` | `(date: Date) => ReactNode` | — | Customize calendar cell content. |
| `open` | `boolean` | — | Control whether the panel is open. |
| `defaultOpen` | `boolean` | — | Initial open state. |
| `onOpenChange` | `(open: boolean) => void` | — | Called when the panel opens or closes |

### DateRange

A complete date range uses `readonly [Date, Date]`. With `allowEmpty`, use `OpenDateRange` from the root entry: `readonly [Date | null, Date | null]`. See [DatePreset](date-picker#datepreset) for preset entries.

| Property | Type   | Default  | Description                  |
| -------- | ------ | -------- | ---------------------------- |
| `0`      | `Date` | Required | Start, no later than the end |
| `1`      | `Date` | Required | End                          |
