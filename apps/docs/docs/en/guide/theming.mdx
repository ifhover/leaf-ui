# Theming

Configure components with [ConfigProvider](/en/components/config-provider). Start with a primary color, base radius and control height; related sizes and interaction colors are derived for you.

## Start with a few settings

Wrap the application and import the stylesheet once:

```tsx
import { Button, ConfigProvider, Input } from '@sudden3/leaf-ui';
import '@sudden3/leaf-ui/styles.css';

export function App() {
  return (
    <ConfigProvider theme={{
      primaryColor: '#7654c6',
      borderRadius: 8,
      controlHeight: 34,
    }}>
      <Input aria-label="Project name" placeholder="Project name" />
      <Button>Save</Button>
    </ConfigProvider>
  );
}
```

Omitted settings use defaults. Hover, pressed, soft backgrounds and focus colors follow the primary color automatically.

## Derived sizes

The defaults are a 10px base radius, 34px control height and 14px font size:

| Base setting | Derived values | Default result |
| --- | --- | --- |
| `borderRadius` | Small radius × 0.6; large radius × 1.6 | `6px / 16px` |
| `controlHeight` | Small height − 6px; large height + 6px | `28px / 40px` |
| `fontSize` | Small font − 2px; large font + 2px | `12px / 16px` |

Numbers are pixels; CSS lengths with units are also accepted. Buttons, inputs and pickers share the same sizes.

## Regional themes

Nested providers override only supplied settings, including individual token overrides:

```tsx
<ConfigProvider theme={{ primaryColor: '#20834a', controlHeight: 36 }}>
  <Button>Default region</Button>
  <ConfigProvider theme={{ primaryColor: '#7654c6', borderRadius: 16 }}>
    <Button>Campaign region</Button>
  </ConfigProvider>
</ConfigProvider>
```

Floating panels, Modal, confirmations and messages inherit their calling region’s theme. ConfigProvider manages confirmations and messages automatically; descendants call useConfirm and useMessage. Set `locale` separately for built-in text.

## Appearance and switching

```tsx
import { useState } from 'react';
import { Button, ConfigProvider } from '@sudden3/leaf-ui';

export function ThemeSwitch() {
  const [dark, setDark] = useState(false);
  return (
    <ConfigProvider theme={{ appearance: dark ? 'dark' : 'light' }}>
      <Button onClick={() => setDark(!dark)}>Switch appearance</Button>
    </ConfigProvider>
  );
}
```

Dark appearance supplies suitable text, surface, border and status colors. Explicit primary colors keep their value. Pair very light brand colors with a suitable `onPrimaryColor` override.

## Advanced overrides

Use `theme.tokens` when you need specific derived sizes, semantic colors, surfaces, typography, motion or overlay stacking:

```tsx
import type { LeafTheme } from '@sudden3/leaf-ui';

const theme: LeafTheme = {
  controlHeight: 36,
  borderRadius: 8,
  tokens: {
    controlHeightSm: 28,
    borderRadiusLg: 18,
    infoColor: '#1677ff',
    motionDuration: 200,
  },
};
```

Explicit small and large sizes take precedence over derived values. See [LeafThemeTokens](/en/components/config-provider#leafthemetokens) for all options.

## Tune the interaction rhythm

The default base duration is 200ms. Press and hover feedback use a shorter duration; selection, disclosure and overlays use timing suited to their change. Row reordering and dialog height changes continue from the current visual position.

Use `tokens.motionDuration` to adjust the region's pace, `motionEasing` for ordinary transitions, and `motionSpring` for selection and shape changes:

```tsx
<ConfigProvider theme={{ tokens: {
  motionDuration: 240,
  motionEasing: 'cubic-bezier(0.22, 1, 0.36, 1)',
  motionSpring: 'cubic-bezier(0.22, 1.28, 0.36, 1)',
} }}>
  <YourProduct />
</ConfigProvider>
```

`motion: false` stops CSS and JavaScript animations in the region, including loading rotation and portals. An inner `motion: true` region can resume motion. The system's reduced-motion preference always takes precedence. Direct interactions such as typing, dragging and cropping respond immediately.

Surfaces and text use neutral grays, with the primary color reserved for actions and selection. Use `subtleTextColor`, `raisedSurfaceColor`, `borderHoverColor` and `shadowXs` to refine the hierarchy.

## Reuse styles in your own components

Read the current region's CSS variables in your application styles. Use ConfigProvider to configure Leaf UI, and `var()` to make custom components follow that configuration:

```tsx
<ConfigProvider theme={{ primaryColor: '#7654c6', borderRadius: 8 }}>
  <button className="product-button" type="button">Custom button</button>
  <Button>Leaf UI button</Button>
</ConfigProvider>
```

```scss
.product-button {
  min-height: var(--leaf-control-height);
  padding: 0 14px;
  border: 0;
  border-radius: var(--leaf-radius);
  background: var(--leaf-color-primary);
  color: var(--leaf-color-on-primary);
  font-family: var(--leaf-font-family);
  font-size: var(--leaf-font-size);
  font-weight: var(--leaf-font-weight);
  cursor: pointer;
}
```

| Variables to read | Purpose |
| --- | --- |
| `--leaf-color-primary` / `--leaf-color-on-primary` | Primary background and foreground |
| `--leaf-color-danger` / `--leaf-color-success` / `--leaf-color-warning` / `--leaf-color-info` | Semantic colors |
| `--leaf-color-text` / `--leaf-color-text-muted` | Main / secondary text |
| `--leaf-color-surface` / `--leaf-color-surface-muted` / `--leaf-color-border` | Surfaces and borders |
| `--leaf-radius` / `--leaf-radius-sm` / `--leaf-radius-lg` | Base / small / large radius |
| `--leaf-control-height` / `--leaf-control-height-sm` / `--leaf-control-height-lg` | Base / small / large height |
| `--leaf-font-family` / `--leaf-font-size` / `--leaf-font-weight` | Typography |
| `--leaf-motion-duration` / `--leaf-motion-fast` / `--leaf-motion-slow` | Base / fast / layout transition duration |
| `--leaf-motion-easing` / `--leaf-motion-spring` | Ordinary / spring easing |

Place custom components inside the intended provider. Import the compiled `styles.css`; consumers do not need Sass.

## Server rendering

Static CSS and dynamic themes work together without generating CSS at runtime. See [SSR usage](/en/guide/ssr) for Next.js and other frameworks.

## Spacing, typography and component overrides

`spacing` derives small and large spacing. `lineHeight`, `headingWeight` and `elevation` configure body line height, heading weight and shadows. Keep configuring through ConfigProvider; use `theme.components` for scoped component overrides:

```tsx
const theme = {
  spacing: 8, lineHeight: 1.6, headingWeight: 600, elevation: 'soft',
  components: {
    Button: { borderRadius: 6, padding: '0 18px' },
    Input: { borderRadius: 6, controlHeight: 36 },
    Card: { padding: 16, shadow: '0 6px 20px #0001' },
  },
} satisfies LeafTheme;
```

Use exported component names. Each component consumes tokens relevant to its layout: input controls use radius, height, background and font size; containers use padding and shadow; layout components use gaps. For further changes, use component `className` / `style` and popup `popupClassName` / `popupStyle`.

## System appearance, responsive breakpoints and contrast

```tsx
import { ConfigProvider, colorContrast, useBreakpoint, useSystemAppearance } from '@sudden3/leaf-ui';
function Application() {
  const appearance = useSystemAppearance('light');
  return <ConfigProvider theme={{ appearance, breakpoints: { md: 800 } }}><Content /></ConfigProvider>;
}
function Content() {
  const { md } = useBreakpoint({ md: false });
  return <p>{md ? 'Wide layout' : 'Compact layout'}</p>;
}
const contrast = colorContrast('#ffffff', '#20834a');
```

`useBreakpoint` reads breakpoints from the current region for your application layout. Grid's existing `sm/md/lg` CSS rules still use the fixed breakpoints listed in its docs. `colorContrast` returns a WCAG contrast ratio, or `null` for invalid colors. Transparent colors are composited with the background and optional third canvas argument. Aim for 4.5 for ordinary text, or 3 for large text.

System preferences update after client hydration. For SSR, start with a server Cookie or a consistent fallback; see [SSR](/en/guide/ssr).

## LeafComponentTokens

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `borderRadius` | `string \| number` | — | Border radius; numbers are pixels. |
| `controlHeight` | `string \| number` | — | Base control height, deriving other sizes. |
| `padding` | `string \| number` | — | Padding for content or a highlighted target. |
| `gap` | `string \| number` | — | Gap between items; numbers are pixels. |
| `fontSize` | `string \| number` | — | Font size; numbers are pixels. |
| `color` | `string` | — | Color or semantic tone. |
| `background` | `string` | — | Component surface background. |
| `shadow` | `string` | — | CSS box-shadow value. |

## Density and portable colors

Use `<ConfigProvider density="compact">` to reduce control heights and spacing throughout a region, including portals. Explicit theme sizes take precedence. Derived colors are calculated in JavaScript; static light/dark palettes support standalone CSS and SSR. Pass concrete colors for a deterministic first frame; CSS variables resolve in the browser.

See [Browser compatibility](./compatibility), [Design resources](./design-resources) and [Visual standards](./design-standards).
