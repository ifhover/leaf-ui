# Theming

Set colors, corner radii and dark mode through ConfigProvider's `theme`. A few settings are usually enough; related styles update automatically.

## Change colors and corners

Wrap your application in ConfigProvider. This example uses a purple primary color and an 8px base radius:

```tsx lineNumbers file="../../../src/examples/en/theming/basic.tsx"
```

</ComponentExample>

Replace Button with your application content. Buttons, fields, selectors and popups share the theme. Hover, pressed and focus colors derive automatically.

Text on primary backgrounds prefers white and switches to black when white has a contrast ratio below `2.8:1`. For example, blue `#1d9bf0` and orange `#ff6900` use white text, while bright yellow `#ffee00` uses black text. Set `theme.tokens.onPrimaryColor` to choose an explicit text color.

`borderRadius` sets the base radius. Cards, dialogs and other surfaces derive radii for their own level, so you do not need to configure each component. Numbers represent pixels; CSS lengths such as `'0.5rem'` also work.

### Common settings

These fields all belong inside `theme`. Set only what you want to change.

| Setting | Example | Purpose |
| --- | --- | --- |
| `primaryColor` | `'#7654c6'` | Set the primary color and derive related interaction colors. |
| `borderRadius` | `8` | Set the base radius; use `0` for square corners. |
| `appearance` | `'light'` / `'dark'` | Choose light or dark appearance. |
| `controlHeight` | `40` | Set the base single-line control height; small and large sizes follow. |
| `fontSize` | `14` | Set the base component font size. |
| `fontFamily` | `'Inter, sans-serif'` | Set the font family; your application loads the font files. |
| `motion` | `false` | Disable regional animations while keeping interactions available. |

Unspecified fields inherit the outer configuration. Defaults are light appearance, a 10px base radius, 36px base control height and 14px font size.

See [LeafTheme](/en/components/config-provider#leaftheme) for all theme fields. For individual text colors, backgrounds or sizes, use [LeafThemeTokens](/en/api/theme-tokens#leafthemetokens).

The default style adds no tokens. Omit `density` for its default value. Automatic hover, active, focus and primary label colors come from the library, so these values do not need to be copied into your configuration. The examples only customize shadow feedback where the style calls for it.

Custom styles only define their differences: radius, border width, a global `tokens.borderColor`, shadows, and tinted surfaces using `color-mix()`. A single border color applies to all component frames, including solid buttons, switches, cards, tables and popups. Individual component overrides take precedence; error and selected states keep their meaning. Components that are borderless by design stay borderless.

`createExampleTheme('illustration', '#1d9bf0')` sets the primary color. Tinted surfaces and borders use `var(--leaf-color-primary)`, and shadows reuse `var(--leaf-color-border)`, so they update automatically without listing a new palette for each color. Omit the color argument to inherit the surrounding theme. Base surfaces keep the library's automatic light/dark palette; tinted backgrounds mix the primary color into those surfaces.

Windows XP and Material are style examples made with Leaf UI theme settings. Windows XP keeps the current primary color and uses bevels, typography and a gradient for a retro feel. Material uses locally available Roboto or fallback fonts. The skeuomorphic style uses `light-dark()` for light/dark surfaces and `color-mix()` to tint them with the primary color; neutral bases and lighting do not need a separate palette for each primary color. Component overrides only customize the card header gradient and button shadow feedback; global borders and shadows remain shared.

Changing styles keeps child components mounted, preserving input and selection values. Popups and service feedback inherit their calling region's theme. Expand the example source to view the complete theme definitions and copy them into your project's `ConfigProvider`. Applications provide their own illustrations, textures and font files.

## Use dark mode

Set `appearance: 'dark'`. Use `'light'` to switch back:

```tsx
<ConfigProvider theme={{ appearance: 'dark' }}>
  <App />
</ConfigProvider>
```

Component text, backgrounds and borders change together. When `primaryColor` is omitted, the appearance supplies its default primary color. An explicit primary color keeps its value: black buttons retain a black fill and white labels in dark mode, with a subtle boundary when needed.

Primary text, selected indicators and focus colors derive separately. In dark mode, text targets `4.5:1` contrast against content and muted surfaces, while selected indicators target `3:1`. Only insufficient colors gain lightness; solid button fills stay unchanged. Blue and orange retain their original fills and white labels. Explicit foreground, focus and interaction tokens still take precedence. CSS color expressions participate after browser resolution without modifying the supplied theme object or color picker value.

ConfigProvider styles the components in its region. It does not add a background to the page's `body`. To update your own page backgrounds and text, use the [CSS variables](#use-the-theme-in-application-css) below.

### Follow the system

Use `useSystemAppearance` and pass its result to `theme.appearance` to follow the operating system:

```tsx
import { ConfigProvider, useSystemAppearance } from '@ifhover/leaf-ui';

export function AppTheme() {
  const appearance = useSystemAppearance('light');

  return (
    <ConfigProvider theme={{ appearance }}>
      <App />
    </ConfigProvider>
  );
}
```

The `'light'` argument is the initial appearance. After mounting, the hook reads and watches system preferences. Your application stores manual choices and decides when to keep following the system.

## Adjust control size and density

For one control, prefer its `size="sm"` or `size="lg"` prop. To make an entire region more compact, set ConfigProvider's `density`:

```tsx
<ConfigProvider density="compact">
  <App />
</ConfigProvider>
```

`density` is a sibling of `theme`. It defaults to `'comfortable'`. The `'compact'` preset tightens control, form and popup spacing and changes the base control height from 36px to 30px without reducing text size.

Set `theme.controlHeight` when you need an explicit height; it overrides the density preset. For example, `controlHeight: 40` produces 34px / 40px / 46px controls. See [ConfigProvider](/en/components/config-provider#base-height) for a size comparison.

## Advanced customization

Use the settings below when your design needs more specific overrides. For colors, corners and appearance, the basic settings above are sufficient.

### Override individual colors or sizes

Use `theme.tokens` for specific styles beyond the basic settings. This example adjusts the success color, large radius and animation duration:

```tsx
import type { LeafTheme } from '@ifhover/leaf-ui';

const theme = {
  primaryColor: '#7654c6',
  borderRadius: 8,
  tokens: {
    successColor: '#20834a',
    borderRadiusLg: 18,
    motionDuration: 160,
  },
} satisfies LeafTheme;
```

Pass this object to `<ConfigProvider theme={theme}>`. Here, `borderRadiusLg` overrides the derived large radius, and numeric `motionDuration` values are milliseconds. See [LeafThemeTokens](/en/api/theme-tokens#leafthemetokens) for the complete reference.

For a very light primary color, use `tokens.onPrimaryColor` to set the text color on solid primary buttons. Check readability in normal, hovered and disabled states after changing your palette. `motion: false` disables regional animations; system reduced-motion preferences always take precedence.

### Style one component type

`theme.components` assigns styles by component name. For example, use 4px button corners and change card padding:

```tsx
<ConfigProvider theme={{
  components: {
    Button: { borderRadius: 4 },
    Card: { padding: 24 },
  },
}}>
  <App />
</ConfigProvider>
```

See [LeafComponentTokens](/en/api/theme-tokens#leafcomponenttokens) for style fields, and each component's documentation for the fields it supports.

`theme.components` changes styles. To set default button `size`, `variant` or other component props, use ConfigProvider's separate `components` prop; see [Component defaults](/en/components/config-provider#component-defaults).

### Borders, shadows and interaction states

`tokens.borderWidth` sets outer borders on controls and content surfaces. `controlShadow` and `surfaceShadow` set control and content surface shadows. Section dividers keep their own fine lines. Component `borderWidth` and `shadow` take precedence over global values.

Components supporting state overrides also accept `hover`, `active`, `focus` and `disabled` colors, backgrounds, border colors and shadows:

```tsx
<ConfigProvider theme={{
  tokens: { borderWidth: 2, controlShadow: '3px 3px 0 #252525' },
  components: {
    Button: {
      borderColor: '#252525',
      hover: { shadow: '4px 4px 0 #252525' },
      active: { shadow: '1px 1px 0 #252525' },
      disabled: { shadow: 'none' },
    },
    Input: { focus: { borderColor: '#7654c6', shadow: '0 0 0 3px #7654c630' } },
  },
}}>
  <App />
</ConfigProvider>
```

State settings change appearance without changing events, dimensions, disabled or read-only behavior, or removing keyboard focus outlines. Nested providers merge each state's fields; `undefined` inherits. See [theme tokens](/en/api/theme-tokens#leafcomponenttokens) for fields and support scope.

### Use the theme in application CSS

ConfigProvider exposes `--leaf-*` CSS variables within its region. Your own content can read them to follow color and appearance changes:

```tsx
<ConfigProvider theme={{ appearance: 'dark' }}>
  <section className="app-panel">Application content</section>
</ConfigProvider>
```

```css
.app-panel {
  padding: 16px;
  color: var(--leaf-color-text);
  background: var(--leaf-color-surface);
  border: 1px solid var(--leaf-color-border);
  border-radius: var(--leaf-radius);
}
```

| Common variable | Purpose |
| --- | --- |
| `--leaf-color-primary` | Current primary color. |
| `--leaf-color-primary-ink` | Primary text, lifted for contrast on dark surfaces. |
| `--leaf-color-primary-indicator` | Primary selected, progress and outline indicators. |
| `--leaf-color-primary-focus` | Default primary focus outline. |
| `--leaf-color-primary-fill-border` | Subtle solid primary boundary, normally transparent. |
| `--leaf-color-on-primary` | Text on a solid primary background. |
| `--leaf-color-text` / `--leaf-color-text-muted` | Primary and secondary text. |
| `--leaf-color-surface` / `--leaf-color-surface-muted` | Content and supporting backgrounds. |
| `--leaf-color-border` | Border color. |
| `--leaf-border-width` | Outer border width. |
| `--leaf-control-shadow` / `--leaf-surface-shadow` | Control and content surface shadows. |
| `--leaf-radius` | Base radius. |

Configure Leaf UI component themes through ConfigProvider and read the results from application CSS. Changing a single base CSS variable does not regenerate the full set of interaction colors.

For Tailwind CSS, import the package configuration to reuse the theme through utilities such as `bg-leaf-surface` and `text-leaf-primary`. See [Tailwind CSS](/en/guide/tailwindcss) for Tailwind 3 / 4 setup.

## Server rendering

Use the same appearance for the server and the client's initial render. To remember a user's choice, read a cookie on the server and supply that initial value. System appearance updates after mounting.

Prefer concrete HEX, RGB or HSL colors. A color such as `var(--brand-color)` resolves after mounting in the browser and cannot guarantee matching derived colors in the server's first frame.

See [Installation & quick start](/en/guide/getting-started) for setup, [server-side rendering](/en/guide/ssr) for frameworks such as Next.js, and [Browser compatibility](/en/guide/compatibility) for support targets.
