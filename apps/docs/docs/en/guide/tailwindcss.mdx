# Tailwind CSS

Reuse Leaf UI colors, radii and spacing in Tailwind.

## Quick setup

For a project with Tailwind installed, choose the configuration for your version. Versions 3.x and 4.x are supported; upgrade first if you use 2.x or earlier.

### Tailwind CSS 4

Declare the cascade layer order before importing styles in your CSS entry:

```css title="app.css"
@layer theme, base, leaf-ui, components, utilities;
@import 'tailwindcss';
@import '@ifhover/leaf-ui/tailwind.css';
```

Leaf UI places all component styles inside `@layer leaf-ui`. Declaring the layer order upfront ensures lazily imported component stylesheets stay below Tailwind utilities so classes such as `w-full` or `w-80` can override default field widths.

<DocsCollapse title="Keep your existing base styles">

To omit Tailwind's Preflight reset, use this entry instead:

```css title="app.css"
@layer theme, base, leaf-ui, components, utilities;
@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/utilities.css' layer(utilities);
@import '@ifhover/leaf-ui/tailwind.css';
```

</DocsCollapse>

### Tailwind CSS 3

Add the preset and adjust `content` to match your source directories:

```js title="tailwind.config.cjs"
const leafPreset = require('@ifhover/leaf-ui/tailwind').default;

module.exports = {
  content: ['./index.html', './src/**/*.{js,ts,jsx,tsx}'],
  presets: [leafPreset],
};
```

Declare the cascade layer order above the Tailwind 3 directives so on-demand component styles stay between `base` and `utilities`:

```css title="app.css"
@layer base, leaf-ui, components, utilities;
@tailwind base;
@tailwind components;
@tailwind utilities;
```

For an existing configuration, append the preset and keep your source paths and plugins.

<DocsCollapse title="Use a TypeScript configuration (3.3+)">

```ts title="tailwind.config.ts"
import type { Config } from 'tailwindcss';
import leafPreset from '@ifhover/leaf-ui/tailwind';

export default {
  content: ['./index.html', './src/**/*.{js,ts,jsx,tsx}'],
  presets: [leafPreset],
} satisfies Config;
```

To disable Preflight, add `corePlugins: { preflight: false }` to the configuration.

</DocsCollapse>

Tailwind tokens map Leaf UI's active purpose roles: `primary` exposes `soft`, `soft-hover`, `border`, `hover`, `active` and `on-primary`; the remaining semantic families expose `soft`, `soft-hover`, `ink` and `on-*` (`danger` and `warning` also include `border`, and `danger` includes `active`). Color names also work with `border-*`, `ring-*`, `fill-*` and similar utilities; type size utilities include the theme line height. Use `generateColorScale` and `generateColorShades` in JS if you need static numeric bands.

## Usage tips

- **Style layers and overrides**: Leaf UI component styles live inside `@layer leaf-ui`. With the `@layer` order above, utility classes such as `w-full` and `w-80` override default component dimensions, spacing and borders; field components also honor `--leaf-field-width` on the field or an ancestor.
- **Global resets**: Unlayered global CSS always overrides layered styles in CSS Cascade Layers. If your application has unlayered global reset CSS, place it inside `@layer base` and import your `app.css` before component stylesheets load.
- **Opacity**: Tailwind 4 supports `bg-leaf-primary/50`. In Tailwind 3, these colors do not support `/50`, `bg-opacity-*` or `text-opacity-*`; define translucent colors in application CSS.
- **Source scanning**: Write complete class names such as `bg-leaf-primary` instead of constructing `bg-leaf-${color}`.
- **Base styles**: A CSS-only page with no Leaf UI component imports also needs `@ifhover/leaf-ui/styles.css`.
- **Breakpoints**: `sm:` and `md:` use your Tailwind configuration, independently of ConfigProvider breakpoints. Follow Tailwind 4's official browser support requirements.
- **Regions and overlays**: Custom Portal content needs the intended theme scope too. Leaf UI overlays synchronize themes automatically. Configure component-specific variables through [ConfigProvider](/en/guide/theming).
